## 2. Regex sites and their matcher (dynamic ones through a core template, named)

All rows are V8-checked by `tests/regex_w1.rs` over `js/regex-sites/w1.mjs` (6,400 results, hand-written edges
plus 500 seeded soups; the other two sites, `field_code_groups` and the `{` `}` scan, are rows of

| Site (TS) | Pattern | Rust |
|---|---|---|
| `textXml` 451 | `text.split(/(\t\|\n\|\f\|\u000B\|‑\|­\| )/)` | a scan of the characters (`char_indices`), the separators are single characters |

## 5. Recursions and their bound

| Recursion | Bound |
|---|---|
| `fieldCodeXml` → itself for each `{ … }` nested part (631–636) | the nesting of braces in the code; the reader never gives more than `max_field_depth` (64). Here `MAX_FIELD_CODE_DEPTH` = 512, past it `DocxError::Write("field code nested too deeply")` (the TS: a `RangeError` around 10,000 levels). Each level re-scans its part, so the work is ≤ 512 × the code length (tested: a 200,000-character code of 100,000 nested braces fails in well under a second) |
| `paraXmlInner` → itself for `pfmt.old` (1008) | one level per `pfmt` inside `pfmt.old.pfmt`: model nesting (the reader gives one) |
| `runXml` → `runXml(fallbackRun)` (custom inline, 496–505) | none: the fallback run has no rare fields, so it goes straight to the plain text path (`plain_run_xml`) |
| `fieldResultXml` → `runXml` of each result run | the results are runs without results (a field inside a result is not nested in the model: one level) |
| `fieldOrRunXml` → `runXml` | no cycle: `runXml` never calls `fieldOrRunXml` |
| `runXml` → `drawingWithParas` → `paraXml` → `genRuns` → `runXml` (text boxes) | the nesting of text boxes (the reader's bound, G20); W2/core stack frames as before |

## 8. Evaluation order around `revisionAttrs` / `mediaRelId` / `linkRelId`

- `revisionRuns`: `plain` and `dels` build the inner XML (its `rPrXml`, which can take revision ids for an
  `rPrChange`, and the inner `w:del` wrappers) **before** `wrapRevision` of the envelope takes its own id: the
  `w:del` ids of a group come before the `w:ins` id around them (`ins` outer, `del` inner). Rust: `inner` first,
  then `w.cx.rev.wrap`.
- `revisionRuns` `plain`: per run, `before`, then `fieldOrRunXml(run)`, then `after` (the comment marks carry no ids).
- `fieldOrRunXml`: the result is built (`fieldResultXml`, its `rPrXml`/revision side effects) **before** the `\h`/
  multi-result test and before `rPrXml(r)` of the complex form; inside a revision `rpr` is taken once for the begin
  character, the code reuses it, and `runXml(r)` takes its own `rPrXml` afterwards.
- `nestedFieldXml`: `rpr` once, the code (pure), then `fieldResultXml(r)` / the formula text.
- `runXml`, edited box/shape: `rPrXml(run)` first, then `editedShapeXml(run)`, then `onceShape(obj, xml)`; text box with
  raw XML: `patchDrawingGeometry` first, then the paragraphs of the box (`paraXml` per paragraph, their revision
  ids), then the replacement.
- `genRuns`: `revisionRuns(inner)` (its ids) first, then `linkRelId` (the only package write of W1; reuses an existing
  relationship with the same external target, else `rIdWnLink<n>`); the tooltip goes before `w:history`.
- `paraXmlInner`: `markIns` then `markDel` take their ids when the `w:rPr` is built, then `pfmt.old` (its own
  `markIns`/`markDel` ids), and `revisionAttrs(pp.pfmt)` last (in the template literal, after `inner`).
- `mediaRelId` is W2's (`picture_xml`, `drawing_xml`); W1 calls them in the TS order and does not touch it.

## 9. Deviations (Opus check first)

| # | Deviation | Why | Needs Opus check |
|---|---|---|---|
| W1-1 | `revKey` compares signature texts in the save's `SigMode` (`Canonical` sorts keys of declared objects) | the core's G23/W-D1 rule for `sameJson`; identical to the TS for objects built in the reader's key order | no (the core's decision applied) |
| W1-2 | `fieldCodeXml` stops at 512 levels with `DocxError::Write` instead of the engine's stack overflow | a Rust stack overflow aborts the process (no-panic rule); the reader's depth limit is 64 | no |
| W1-3 | `gen_runs`' look-ahead `sameLink(k)` is memoised: the scan from k over zero-width marks ends at the same item for every k up to it | the TS look-ahead is quadratic in the number of consecutive marks; same results | no |
| W1-4 | `custom` inline: the fallback run goes to `plain_run_xml` directly | it has no `ext`, so every earlier branch of `runXml` is skipped for it; avoids a `&'a Run` for a temporary | no |
| W1-5 | **`Writer::textbox_paras_xml` made `pub`** (`write/story.rs`, one word, additive) | `runXml`'s text-box branch calls `drawingWithParas(geo, run.textbox.paras)` with **paragraphs only** (no `blocks`, no `tb`), which is `textbox_paras_xml`; `drawing_with_paras` (blocks view, groups) is the other call, from `objectXml` | yes (a signature visibility change in the core) |
| W1-6 | `tests/memory_d1b_writer.rs`: the emitter-stub error path now uses W1's own error (a custom inline with an invalid type) | the test asserted the W1 stub message, which no longer exists | no |
| W1-7 | the `text_xml` input is the text with lone surrogates as U+FFFD (`Utf16::to_string_lossy`), as everywhere (A1.4) | `TextEncoder` encodes a lone surrogate that way; segmentation happens on BMP separators so no pair is split | no |
