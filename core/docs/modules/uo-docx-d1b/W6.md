## 5. Recursions and their bound

None (`findDeep` is `Element::descend`, iterative). Every edit step parses the drawing again, as the TS; the
nesting is bounded by the parser's depth limits.

## 6. Module state and where it lives in `WriteCtx`

`picture-xml.ts` has the module variable `rawSrc` (the text `rawOf` slices, set around `readPictureFormat`
and `patchPic`). It is not needed here: R4b's `read_effects`/`read_picture_format` read the raw slices from
the element's own source (`Element::source_slice`), which is the text the drawing was parsed from. No
`WriteCtx` use (these emitters are called by D2 commands, not by `write_document`, except
`text_effects_xml`, which has no state).

## 8. Evaluation order around `revisionAttrs` / `mediaRelId` / `linkRelId`

None of the three is used. The orders that matter are the TS ones and are kept: the steps of `patchPicture`
(container → `docPr`/`cNvPr` → decorative → locks → `spPr`/`blipFill` → `embed` → blip adjustments → `a14`),
each on the output of the previous; the edits of a step recorded in the TS order and applied from the last
position to the first (a stable sort: two insertions at the same position come out reversed, as the TS).

## 9. Deviations (Opus check first)

| # | Deviation | Why |
|---|---|---|
| W6-1 | `XmlPatch::apply` refuses (`Err`) edits that overlap so that the TS `slice` arithmetic would cut inside a multi-byte character; the TS returns some string | Rust slices at character boundaries; no edit of this file overlaps, and the facet never hit it |
| W6-2 | `replace_wp_prefix` returns `None` (→ `Err`) when a prefix holding `` $` `` or `$'` would make the result pass 256 MiB; the parser accepts such a name (`<a$`b:inline>`), the TS is quadratic there | linear-time/no-DoS rule |
| W6-3 | `PictureChange` is a Rust struct: `dist` an ordered `Vec`, `wrap` an enum (`PicWrapKind`), `Option<Nullable<T>>` where the TS accepts `null` (remove) | typed input of the D2 commands; the JSON of the facet maps onto it field by field |
| W6-4 | the TS `fillXml` `TypeError` paths (`FxFill` without its required parts) are `Err` | item 7 |
| W6-5 | `PicEffects` is rebuilt by `read_effects` (R4b) and edited by field; its key order (which `readEffects` tracks for the digest) is not used by `effectLstXml` | the output order is `EFFECT_ORDER` |
| W6-6 | the `$` in a container prefix is handled with the full `GetSubstitution` (shared with W5), not dropped | faithful to the TS template |
| W6-7 | `BLIP_ORDER` is ported though the TS never reads it | declared constant |
| W6-8 | `XmlPatch`, `PictureChange`, `patch_picture`, `dml_color_xml`, `pic_line_xml` are public and stable: W2 reuses them | the brief's note on W2 |
| W6-9 | `Math.round`-printed attribute numbers print `NaN`/`Infinity`/`-0` as JS (`to_js_string`) | unchanged TS behaviour on non-finite changes |

No deviation changes a result on a reader-built model or on the facet's inputs; none needs an Opus check
beyond W6-3's API shape (the `PictureChange` field types).
