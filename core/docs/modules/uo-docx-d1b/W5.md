## 4. Object/Map orders relied on (JSON keys, `Object.entries`)

None. `NS` is an array (`v`, `o`, `r`); `NAMED`, `MIME`, `TEXT_ES` are looked up by key (own keys only: see
item 9); `WORD_PATTERNS`, the gallery and the lists are arrays in source order.

## 5. Recursions and their bound

None. The loops that search a free `word/media/image{n}.{ext}` and a free `rId{k}` are linear in the parts and
relationships already there (one `contains` each iteration, as the TS); the LZW encoder runs over 64 pixels.

## 6. Module state and where it lives in `WriteCtx`

None: `writePageBackground` keeps no module state. What it adds is **returned** (`BackgroundAdded { rid, media }`)
and the caller passes it back as `prev` on the next save of the same package (the session keeps it: D2a). It
does not use `WriteCtx` (the brief: called by the session and the D2b commands, not by `write_document`).

## 7. `throw` sites → `DocxError::Write`

None reachable (the TS `!` assertions at :336/:342/:362 are on values that exist). `write_page_background`
returns `Ok(None)` where the TS returns `undefined` (no main part, an empty `document.xml`) and `Err` where the
TS throws in `partByRelType` (a relationships part `parseXml` rejects): `DocxError::Package`, same class (D6:
`part_by_rel_type` is the core's).

## 8. Evaluation order around `revisionAttrs` / `mediaRelId` / `linkRelId`

No revision ids, no `mediaRelId`/`linkRelId` (the function writes its own `word/media/image{n}.{ext}` and
`rId{k}`). The package edits happen in the TS order so the part order of the saved zip is the same (the facet
compares it): `prev`'s relationship and image out first; the old element out of the text; the new image
(`setPart`), its relationship (in the rels text), the content-type default; the new element in; the old
image's relationship out when no `"rid"` is left; then `document.xml` and the rels part set (the TS sets them
always; here only when the text changed, W-D10: the same decompressed bytes).

## 9. Deviations (Opus check first)

| # | Deviation | Why |
|---|---|---|
| W5-1 | `write_page_background(pkg, media, bg, prev)` takes the document's `MediaStore` (the TS `img.data` is a `Uint8Array`; the model holds a `MediaRef`) | additive signature of a function no one called yet; **needs Opus check** only as an API shape |
| W5-2 | strings of the specs (`WatermarkTextSpec`, titles, fonts, ids) are Rust `&str`/`String`: a lone surrogate is not representable | dialog inputs, not model text |
| W5-3 | `MIME[ext]` own keys only (`constructor` and `__proto__` print `Object.prototype` text in the TS) | the core's W-D12 |
| W5-4 | dynamic patterns with the values as literals (`prev.rid`, `oldRid`, the extension) | G9 / core W-D5/W-D6 |
| W5-5 | a part is set only when its text changed | core W-D10 |
| W5-6 | `lzw_encode` keys its dictionary by (prefix code, symbol) instead of the sequence string | the same entries: every multi-symbol sequence extends one already in the dictionary; the GIF bytes are compared |
| W5-7 | `watermark_gallery()` builds the 12 items on each call (no static cache) | M5: no cache to bound |
| W5-8 | `rows` of `pattern_gif` is `&[f64]` (`to_int32` per row), not `&[u8]` | the TS shifts a JS number |
| W5-9 | the corpus has no document-level `w:background`: parity runs on seeded fills (4,000) and on the R3 reader's own output | corpus fact, for the milestone gate |
