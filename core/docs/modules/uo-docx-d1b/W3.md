# uo-docx D1b — frontier W3: declarations

Brief: `../uo-docx.md`, "D1b — writer (architecture)", "Emitter frontiers". One table per kind, each row
with the TS file:line. TS files: `write/packages/docx-core/src/table-xml.ts` (`T`) and `serialize.ts` (`S`).
Rust: `crates/uo-docx/src/write/emit/table.rs`.

Ported: `borderXml`, `pgBordersXml`, `gridXml` (done earlier by the core, one correction: item 9), `bordersXml`,
`shdXml`, `widthXml`, `marXml`, `lookXml`, `tblpPrXml`, `onOff`, `val`, the `TBLPR_GEN`/`TRPR_GEN`/`TCPR_GEN` tables
(`Gen<T>` entries: key, schema name, `deepEq` of the field, XML), `genAll`, `tblPrXml`, `tblPrExXml`, `trPrXml`,
`tcPrXml`, `deepEq`, `setKid`, `patch`, `patchTblPr`, `patchTblPrEx`, `patchTrPr`, `patchTcPr`; serialize.ts
`borderXml`/`borderSetXml` (legacy, `w:space="0"`), `TBL_SIDES`/`CELL_SIDES`, `tblPrXml` (legacy), `tcPrXml` (legacy),
`legacyOrTypedTblPr`. New public functions (additive): `tbl_pr_xml`, `shd_xml`, `look_xml`.

## 1. Numeric parse/format sites and the uo-jsnum function used

| Site | Rust |

| T:104 `val(tag, v)` `esc(String(v))` (`tblStyleRowBandSize`, `gridBefore`, `gridSpan`, ...) | `val_num` = `esc_attr(num_str(v))` |
| T:91 `bits.toString(16).toUpperCase().padStart(4, '0')`, bits ≤ 0x7E0 | `{bits:04X}` on a `u32` (non-negative integer: no uo-jsnum needed) |
| T:90 `b(v) = v ? 1 : 0` | `u8::from(v == Some(true))` |
| T:136 `${v.val}` (`trHeight`, not escaped) | `num_str` |

| S:1155 `t.gridColsTwips.reduce((a, b) => a + b, 0) \|\| undefined` | `fold(0.0, a + b.to_number())` (`null` adds 0), then the JS truthiness of a number (`!= 0 && !NaN`), printed by `num_str` (S:1156) |

There is no `parseInt`/`parseFloat`/`Number()` in these functions; no float → int conversion.

## 2. Regex sites and their matcher (dynamic ones through a core template, named)

None in `table-xml.ts` or in the legacy generators. `esc` (T:17, S:38–40) is a chain of `.replace(/…/g)` with fixed
strings: `js::esc_attr` / `esc_text` (one pass over the characters; `&` first in the TS, so the result is the same).
The one regex near the code, `gridOf` (S:1151), is the core's (`matchers::grid_of`). `splitElement` (the raw split of
`patch`) is uo-opc's `split_element` through `lossless::split`, bounded by `cx.limits`.

## 3. Template-literal values printed without escaping

| Site | Value |
|---|---|
| T:121 `<w:tblLayout w:type="${v}"/>` | `tblLayout` (a model string: `fixed`/`autofit` from the reader; anything else is printed as is) |
| T:136 `w:hRule="${v.hRule}"` and `w:val="${v.val}"` | `trHeight` rule and value |
| S:1067 `w:sz="${e.sizeEighthPt}"` | a number (never needs escaping) |
| S:1156, 1166, 1167 `w:w="${total}"`, `w:w="${cell.widthTwips}"`, `w:val="${cell.gridSpan}"` | numbers |
| T:91 the six `w:*="${b(...)}"` and `w:val` of `tblLook` | `0`/`1` and hex digits |

Everything else a string goes through `esc_attr` (`& < > "`), as the TS does: `attrs` (T:20), `val` (T:104),
`escAttr` of the legacy border style, colour and shading fill.

## 4. Object/Map orders relied on (JSON keys, `Object.entries`)

| Site | Rule |
|---|---|
| T:162 `genAll`: `Object.keys(gen)` is the declaration order of `TBLPR_GEN`/`TRPR_GEN`/`TCPR_GEN`; the result is sorted by `order.indexOf(name)` with a stable sort | the Rust tables are slices in the same order; `Vec::sort_by_key` (stable); the `only` set is a key list (`EX_KEYS`) |
| T:228 `patch`: `Object.keys(gen)` order = the order in which `setKid` inserts the new children (matters when several are inserted between the same two raw children) | same slice order |
| T:65 `SIDES` (`top, left, bottom, right, insideH, insideV, tl2br, tr2bl`), T:82 `top, left, bottom, right`, S:1080–1081 `TBL_SIDES`/`CELL_SIDES` | fixed arrays |
| T:188 `deepEq`: `Object.keys` order and `undefined`-valued keys do not matter | field by field (item 9, D-W3-1); the `cleared` mask and the `KeyOrder` of the model objects are not compared |

## 5. Recursions and their bound

None. `deepEq` recurses over fixed-depth shapes (at most `tblBorders` → side → fields); it is typed field by field
in Rust, so it does not recurse. `patch` is a loop over the generator table.

## 6. Module state and where it lives in `WriteCtx`

None in these functions. `WriteCtx` is taken only for `limits` (the bound of `split`); the typed generators keep the
`cx` parameter of the core's call sites (`_cx`) and do not read it.

## 7. `throw` sites → `DocxError::Write`

No `throw` of its own. `splitElement` → `parseXml` throws on a raw element that does not parse (and the limits); Rust:
`lossless::split(...)?`, the uo-opc error converted to `DocxError` (same condition, the message is not compared).
`patch*` is called by the core with raw text from the source store (always well formed) or from a hostile package
(refused with the error). The facet compares `err` against `err` (603 of 6,000 synthetic patches: the unescaped
`tblLayout`/`hRule` strings with `"` or `<` make an element the parser refuses, in the TS and in Rust).

## 8. Evaluation order around `revisionAttrs` / `mediaRelId` / `linkRelId`

None of the three is called by W3. The order that matters inside W3 is the generator-table order (item 4) and, in
`rowsXml`/`tableXml` of the core, `patchTblPr` → `gridXml` → rows, `patchTblPrEx` → `patchTrPr` → cells, `patchTcPr`
before the cell body: unchanged, the core already follows it.

## 9. Deviations (Opus check first)

| # | Deviation | Why |
|---|---|---|
| D-W3-1 | `deepEq` is a typed, field-by-field comparison per table entry (`eq: fn(&T, &T) -> bool`), not a generic walk over `Object.keys`. The verdict is the one of the TS: `===` on numbers (NaN differs from itself, `null` differs from an absent key, `Some(Num)` vs `Some(Null)` differ), key order and `undefined`-valued keys (the model's `cleared`) ignored, an object differs from an absent one. | the model has no generic object walker; the shapes are fixed (`WidthSpec`, `BorderSpec`, `ShadingSpec`, `TblBorders`/`TcBorders`, `CellMargins`, `TblLook`, `TblpPr`, `TrHeight`). Checked by the facet (27,888 results equal, 6,000 seeded synthetic pairs). |
| D-W3-2 | `setKid` is uo-opc's `set_kid` with an empty XML mapped to `None` (T:205 treats `''` as a removal, lossless.ts's does not) instead of a second copy of the function | same logic (`findIndex`, drop the later duplicates, insert before the first child of higher rank, `-1` for a name outside the order); the brief's "its own setKid" is the empty-string rule, kept at the call site |
| D-W3-3 | `border_xml` (T:48, ported by the core earlier): `b.space ?? (nil ? undefined : 0)` now treats `JsNumber::Null` like `undefined` (`??`), as the TS; the core's version printed `null`. Only reachable with a `space: null` in the model, which the reader never writes. **A function of the Opus core touched**, listed for the check; the round trip is unchanged. | faithfulness |
| D-W3-4 | `patch` returns `raw.to_owned()` when nothing changed (the TS returns the same string) | ownership; one copy of a small element |
| D-W3-5 | `Str` values never hold a lone surrogate (`Str = Box<str>`: attribute values from XML), so `esc` and the printed strings need no `TextEncoder` step here | A1.4 |

Need an Opus check: D-W3-3 only (a one-line fix in a function the core owned).
