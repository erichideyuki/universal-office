## The oracle use (the Opus reviewer checks this specially)

Every layout question of the family, where it is asked, with what, and what the session does with the answer.

| Call | Asked by | When | Passed | The session does with the answer | Parity assertion |
|---|---|---|---|---|---|
| `field_values(view, scope)` | `refresh_field_cache` (TS `refreshFieldCache`) | once at the END of `updateFields`, `insertCrossReference`, `insertCaption`, `insertTableOfFigures`, `insertTableOfContents`, `insertTocTemplate`, `updateToc`, `updateTableOfFigures` | `FieldScope::All`, or `Runs(set)`: the added runs (cross-reference, caption + the label's SEQ), the PAGEREF runs of the TOC (`updateToc(pages)`, `updateFields(pages)`), the field runs of the selection | deduplicates by `RunRef` (first place, last value, as the TS `Map`), resolves each to the model run (`field_run_mut`: body, cell, header/footer, note, textbox, group item, field result; anything it does not name is ignored, never a panic) and applies `set_field_result`; counts the changes | `fvs` of the Chromium replay: the number of `field_values` calls per step and, per call, the scope (`A`, or the SAME set of field runs the TS passed as `only`, compared as a sha of the sorted keys) against the TS (`refreshFieldCache` is wrapped in the capture); the values answered are the TS `setFieldResult` calls |
| `shown_page_numbers(view, paras)` | `prepare_pages` (the TS `pageLabelOf`, 6623) | ONCE at the start of a command that builds TOC sources, with the unchanged model | the body (and cell) paragraphs that can be sources of the TOCs the command builds (`collect_toc_rows`: the same rule `tocSources` uses, with the TOC being rebuilt or replaced skipped as `inSkip` does); EVERY body paragraph when the command deletes a selection first or drops the old gallery TOC (F10-A4, below) | one label per paragraph (`String(page.number)`, "1" when the layout has no line for it or the vector is short) kept until the command ends | `pgc` (one call when the TS called `pageLabelOf`, none when it did not) and `pgv` (every paragraph the TS asked about, by its ordinal at the start of the step, is in the request) of the Chromium replay; M3: one call per command, the request bounded by the sources |
| `next_hyphenation(view, from, skip)` | `next_manual_hyphenation` | at each `nextManualHyphenation` and again, one layout per rejected word, from the offset after a candidate whose word has fewer than 2 letters | `DocRef` of `(body block of the paragraph, offset)`, the skip set of `(ParaId, start)` | the candidate's block becomes a paragraph; past the selection's end the search stops; otherwise the word is proposed | `mhc` (the layout is asked when the TS got a word; at most once otherwise) and `res`/`mh` (the word, its points, the state) of the Chromium replay, which answers the word the TS got; the behaviour tests (`manual_hyphenation_*`) for the re-ask (F10-D4) |

`shown_page_numbers` is a THIRD method of the trait (`view.rs`, F10-D5): the TS `pageLabelOf` reads the editor's last layout
(`eng.lines`) for every TOC, table-of-figures and gallery entry, and `G21`/K17c dropped `pages_of` on the claim that the TOC
numbers come only through `onField` — this call site exists and is observable (it decides the change count of `updateFields` and
every PAGEREF the layout does not report). Its default body ANSWERS AN ERROR (`Internal`, "not implemented by this oracle"):
a quiet default (label "1") would silently change results. The orchestrator implements it in `uo-docx-layout/src/oracle.rs`
from the last layout (`Layout::line_index` + `page_of`); until then the real `EngineOracle` fails the commands that build TOC
sources with a layout error (rolled back, F10-D1).

## Decisions outside the TS semantics

| # | Decision | Why |
|---|---|---|
| F10-D1 | A `LayoutError` after the command changed the model rolls the step back (`history.discard` + `restore_state`) and answers `CommandError::Layout`. As declared (pinned by `session_d2b_f10.rs`): (a) `restore_state` applies the undo's JSON round trip, so EVERY paragraph id is renewed and the symbol keys are dropped, as after an undo; (b) `Session::exec` answers `Err` with no ChangeSet, so a host that keys a cache by ParaId must re-sync completely on `CommandError::Layout`; (c) the step snapshot is not deep (as the TS `snapshot()`): the `_Ref` that `insertCrossReference` (footnote/endnote, kind page) puts IN the note's story, and `refSeed`/`next_bm_id`, stay; (d) `insertTable` with AutoCaption: when the caption's layout question fails the TABLE's step goes too (the whole command is undone, the history length and the dirty flag are as before; the nested `snapshot()` forgets which step made the document dirty, `rollback_nested_step` restores it) | the TS throws and leaves the partial change |
| F10-D2 | `refSeed` is drawn at the first hidden `_Ref`/`_Toc` name (`env.random_u32()`), `set_ref_seed` fixes it | the TS draws at element construction; the session has no construction hook |
| F10-D3 | The hyphenation patterns come through `Session::set_hyphenation_registry` (the layout engine's `Arc<HyphenationRegistry>`); without one the points are the soft hyphens the word has | the TS loads them asynchronously (shell) |
| F10-D4 | `next_manual_hyphenation` asks again (one more forced layout) from the offset after a candidate whose word has fewer than 2 letters. Cost: the TS does ONE layout; the session does one per rejected word, at most `MAX_ASKS` = 1,000 per command (it was 100,000: a hostile document, e.g. soft hyphens between digits, would have cost that many full layouts). At the bound the search ends with no word, as at the end of the document (F10-D24) | the TS walks every forced line; the oracle answers the first candidate |
| F10-D5 | The third oracle method `shown_page_numbers` (see above) | G21 revisit |
| F10-D6 | A field nested two levels down in `fieldResult` cannot be addressed by a `RunRef` (`RunSub` holds one level): not updated | the oracle's names stop there |
| F10-D7 | A `TocField` records the index of its begin/end run; at rebuild the run is found again by being a begin/end run (the TS `indexOf` by identity) | runs are values here |
| F10-D8 | At most 10,000 caption labels in the settings | M5; the TS is unbounded |
| F10-D9 | `ss` of a date pattern is 00 (`DateParts` has no seconds) | a D2a struct change would touch every literal |
| F10-D10 | Spanish dates carry Portuguese month and day names | the TS `formatWordDate` uses the PT table for every non-English locale; replicated |
| F10-D11 | Instructions, labels and bookmark names are `&str`: a lone surrogate becomes U+FFFD | the model stores field instructions as `Str` |
| F10-D12 | A table formula whose result the TS cannot format (`toFixed` past 100 digits throws) is left as it is | no panic, no partial update |
| F10-D13 | `stylesEditable()` is always true | the session never loads an ODT |
| F10-D14 | `this.sect()` is the body's final `sectPr` in every context (as F7) | the context models share it |
| F10-D15 | The text of a note in the Footnote/Endnote items is the note's top-level paragraphs | D2a-C1 / F5-D1 |
| F10-D16 | A hyphenation candidate that is not a top-level body paragraph ends the search | the oracle answers the body's lines |
| F10-D17 | The TOC commands report `touch_all` | they change the body and the bookmarks of every story |
| F10-D18 | `addTextPlan` with a NaN level: `{ heading: NaN }` is falsy (nothing happens), `{ outline: NaN }` writes `outlineLvl` NaN, as the TS | faithful |
| F10-D19 | `insertAlignmentTab` refuses an alignment, `relativeTo` or leader outside the TS unions (`left/center/right`, `margin/indent`, `none/dot/hyphen/underscore/middleDot`) | the values go into attributes of `w:ptab`; the TS types guarantee them, a JS caller's garbage must not reach the file |
| F10-D20 | `insertTableOfFigures` and `insertTableOfContents` refuse a tab leader outside `TabLeader | 'none'` (`dot`, `hyphen`, `underscore`, `heavy`, `middleDot`, `none`) | the value goes into `w:leader` of every entry's tab; found by the big no-panic run (`q"uote` wrote a file that did not reopen) |
| F10-D21 | `prepare_pages` skips the TOC being rebuilt (`inSkip`) and, when the command deletes a selection before it reads the sources or drops the old gallery TOC, asks for EVERY body paragraph (F10-A4) | found by the Chromium replay: the sources of the TS are read AFTER those mutations (a paragraph the deletion merges becomes a heading), which the unchanged model cannot predict; still ONE call |
| F10-D22 | **TC fields are read from the live paragraph and a TC run is visited twice.** In the TS `tocSources`, `for (const r of p.runs)` reads the TC fields while `refBookmark` -> `addBookmarkMarks` SPLICES the mark runs into that same `p.runs` (at or before the TC run's index). The iterator therefore meets the same TC run a second time, with `at` carrying on from `acc`; the second `refBookmark` finds the `_Toc` just made (for a TC run of empty text, e.g. from `markTocEntry`, the range is the same) and the TOC gets ONE MORE entry for it. This happens every time the `_Toc` is new (after `dropOldTocMarks`: every update). Replicated: `toc_sources` walks the live paragraph by index (bounded by `TC_WALK_VISITS`); a row with no host story keeps the precomputed list (nothing can splice there). Found by the review (it was the unexplained F10-A5); the Chromium replay of `alt-inventada-00.docx` matches from step 32 on; test `a_tc_field_of_a_heading_is_listed_twice_as_the_ts_iterator_does` | frozen TS behaviour, 1:1 |
| F10-D23 | **`insertCrossReference` with `position` (the stale first run, the former F10-A2).** In the TS `insertRefFields`, the second `insertWholeRun` (after the space) replaces the model's run object of the first field; the `only` set passed to `refreshFieldCache` still holds the first (now stale) object, so the TS layout never reports it and the first field's cached result stays "?" in the saved file. The session's `only` holds position-based `RunRef`s, so with the real oracle BOTH fields get their value: the first REF/PAGEREF result is "?" in the TS and the computed value in Rust. NOT replicated (a Rust-only improvement of a TS bug); the replay cannot see it (it answers only the values the TS reported; the scope is compared by size, `fvs` `R<n>:?`). Maintainer decision (gate item 6) | values have no stale object identity |
| F10-D24 | `MAX_ASKS` of `next_manual_hyphenation` is 1,000 (see F10-D4); the replay oracle ignores `from` and `skip` (the recorded word is the TS answer), so those arguments are checked by the behaviour tests only | M5 |
