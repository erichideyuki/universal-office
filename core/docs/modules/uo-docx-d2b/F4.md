Completed in D2a's files (declared below): `SectionState::effective` (line numbers, vertical alignment and the own column

(`Session::restore_settings`: `eo`, `dt`, `hy`, `bg`/`bgd`, `np` with the TS rule "a value that differs is applied"),

## Regex sites

None of the F4 TS files that were ported uses a regex except `newHfTarget`'s `/\bId="([^"]+)"/g` (hand scan, `\b`
before `I`: the previous byte is not a word character) and `pageNumberGroupIds`' (W5, ported). Not covered by V8 rows:
the hand scan is exercised by the unlink tests.

## Key orders built (U6)

`sp.type/vAlign/lnNumType/cols/titlePg/pgNumFmt/…` are `obj::set`/`delete`/`set_undefined` (a new key goes last; `sp.cols = undefined` is
a key holding `undefined`); the break `{ sectPr, headerRefs, footerRefs, raw?, id }`; the effective `sect.lnNumType` is
copied in the key order of `sp.lnNumType` (`{ ...sp.lnNumType }`); `colDefs` then `equalWidth`; `PageFill` literals
(`gradientGeometry` per style, then `color`, `color2`, `method`/`colors`); `PageBackground` `{ color, themeColor,
themeTint|themeShade }`. The two key orders of the hyphenation settings are kept because the TS compares
`JSON.stringify(next) === JSON.stringify(cur)`: `{ auto, caps, zone, limit }` from the file and `{ auto, caps, limit,
zone }` once edited, so an edit that changes nothing can still take a step when a zone is set (replicated, F4-D11).

## Events (in the order the TS dispatches them)

`hfSectionOp`: `uw-change` (snapshot), then `uw-hfmode` `{active}` after the return to the page (none for the silent
exit); the new part of an `enterHeaderFooter` inside it adds `uw-styles-change` (the style entering `styles.xml`) and
`uw-dirty-change` when it changes; `setLineNumbering*`/`setPageSetup` with numbers on: `uw-styles-change` for the
`Nmerodelinha` style (outside a step); undo/redo with the layout's answer may add the same.

## Decisions outside the TS semantics (for the milestone gate)

| # | Decision | Why |
|---|---|---|
| F4-D1 | The layout's answers are ARGUMENTS: `HfAt` (`hfContext()`: section and variant), `hf_section` (`pageSections[hfActivePage]`), `HfReenter` (the part the page shows after the change: an existing part, or the part `enterHeaderFooter` creates), and `undo_reentering`/`redo_reentering` for the return after an undo (D2a-C2). No change to `LayoutOracle` | the brief; isolated in `header_footer.rs` |
| F4-D2 | A header/footer part that an undone unlink left behind is freed when the index doubles (no section and no history step refers to it); the slot is reused; the file's parts are never freed. The TS keeps them (and numbers rIds/paths on); after a free the Rust may reuse an rId or a path. Cap `MAX_HF_PARTS` = 10,000 | M2 (a long unlink/undo script grew the index); the saved file differs only in a name never seen by a reader |
| F4-D3 | A header/footer part with a table is edited through its top-level paragraphs (D2a); the TS flattens the cells into its editing list. The session harness leaves such documents out | the D2a-C1 family: one gate decision for notes and header/footer |
| F4-D4 | Hostile sizes: columns are capped by `maxColumns`, `columnWidths` by 1,000,000; a command that cannot place its break (position outside the story) takes no step (D2a-T1) | the TS throws |
| F4-D5 | In a cell, note or header/footer the section commands see the CONTEXT model: no breaks, so section 0 is the body's last `sectPr` — as the TS (`this.model.sectPr`), including `pageBorderTargets` using the body model | replicated quirk |
| F4-D6 | `columnsPresetOf` with fewer widths than the preset needs answers "no preset" | the TS throws on `undefined.widthTwips` |
| F4-D7 | The page-background comparison at the save is structural on the model (image by media reference) instead of the TS key (image by size and three samples) | the same background re-set to equal bytes writes the same part either way |
| F4-D8 | `lnMemory` is keyed by the section id and cleared at every undo/redo (the TS keys the `sectPr` object, which the JSON round trip replaces) | same observable behaviour |
| F4-D9 | Reading `bodyRefs` does not create it (the TS `??=` does); the capture normalises "absent" and "both lists empty" | not observable |
| F4-D10 | The restored selection of `ExitHeaderFooter` is clamped to the story (D2a-C4) | the big no-panic sweep: a stale selection after an undo taken in header mode |
| F4-D11 | `hyphenation_json` compares in the two key orders | replicates the TS no-op test |

Replicated TS quirks (not decisions): `setPageSetup` with `applyTo` other than section/document is refused outside the
body; `setLinkToPrevious(on, kind)` returns when `on === own` is false in the two senses (an already linked part and an
already unlinked one do nothing); the unlink copies the inherited part with the TS rule "from XML when the source was
never edited"; `enterHeaderFooter` inside `hfSectionOp` creates the part the page needs when the section has none;
`saveDocx` in header mode syncs the sections (the TS leaves the edit and returns); `removePageNumbers` keeps tables and
appends a fresh paragraph when none is left; `setEvenOddFlag` is applied again by an undo whose step value differs.

## Memory (measured; see the run output)

M1 (`memory_d2b_f4.rs`): 38 whole session lives (corpus sample with plausible and hostile commands, the constructed
documents, undo/redo, save) and the error and refusal paths return the live bytes (0 B), first run. M2: 300 cycles of
unlink / relink / undo / redo / page colour / section break: flat in parts (256 slots; the rest of the growth,
about 5 KB per created part, is the part's sources and relationships, bounded by the cap and the free of unreferenced
parts). M3 on a generated 500-page document (15,000 paragraphs, 51 sections): one section break 141 KB, a page break
44 KB, a column preset 47 KB, a page setup of the whole document 1.7 MB (52 `sectPr` and the effective sections, once).

## Security (no panic)

`nopanic_d2b_f4.rs`: hostile arguments (margins/widths/counts NaN, ±∞, 1e300, section and part indices at `u32::MAX`, a
part to return to that does not exist, the editor locked in the middle) in every command over corpus documents and
byte-mutated ones, with undo/redo storms and a save that reopens. Default 33 documents × 60 steps (seconds);
`UO_NOPANIC_BIG=1`: 254 documents × 150 steps, all saves reopened; 11 mutated documents opened, 64 refused. Found: the
body selection restored by `ExitHeaderFooter` could lie outside the story (F4-D10).
