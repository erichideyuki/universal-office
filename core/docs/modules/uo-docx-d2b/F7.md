# uo-docx D2b-F7 — drawing objects, text boxes and pictures (declarations and process metrics)

Frontier D2b-F7 of `uo-docx`: the session commands of the shapes, text boxes, groups and pictures, the selection pane
and the picture commands that need the shell's pixels (two-phase). Files: `src/session/ops/drawing.rs`,
`src/session/ops/drawing/{loc,pure,rx,textbox}.rs`, `src/session/ops/pictures.rs`; tests `tests/{parity_d2b_f7_ops,
parity_d2b_f7_session,regex_d2b_f7,session_d2b_f7,memory_d2b_f7,nopanic_d2b_f7}.rs` and `tests/d2b_f7_support/mod.rs`;
scripts `js/capture-d2b-f7-ops.mjs`, `js/capture-d2b-f7-session.mjs`, `js/regex-sites/d2b-f7.mjs`. The work started as a
partial implementation (commit `6471786d`) and was finished in place.

## Key orders built, identity per construction site

All objects the TS builds by literal or spread go through `obj::set`/`obj::assign` as in the other families (the new box run, the new image run, the user
item). New runs: `textbox_run_from_xml` (a new `Run`, no `src`), `insert_image_apply` (a new `Run` with the props copy's `rpr_link`; the settle turns it into the run's `rpr` as the TS layout pass does), the pieces of a
split run (new `Run`s). Format edits patch the run in place (`make_mut`), `apply_drawing_xml` keeps the selection with the run (below).

## Two-phase jobs

| Command | Round 1 | Round 2 | Step taken |
|---|---|---|---|
| `Insert` | `DecodeImage` (size) | | when the decode is in (`Failed`: no step) |
| `Change` | `DecodeImage` (size) | | when the decode is in |
| `SetAdjust` | `DecodeImage` (pixels) | `EncodeImage` (the processed pixels; PNG) | after the encode; a neutral adjust asks no job |
| `Compress` | `DecodeImage` per picture | `EncodeImage` per picture (JPEG 0.85 or PNG) | after the encodes; `compress_result()` = pictures changed |
| `SetWrap`/`SetLayout` Tight/Through | `DecodeImage` (pixels) | | `SetLayout` waits for the pixels as a whole (the TS applies the contour and the rest of the dialog in one step; this session fixed the partial implementation, which dropped the contour) |

`complete()` stashes every answer in arrival order (at most 4,096 per command, M5); a command with several jobs takes all of them before it continues. `Session::cancel_pending` (`session/mod.rs`, a line of the shared file) calls `F7State::clear_pending`, which drops the stash, the stage and the encode flag, so a cancelled Compress/SetAdjust (after some decodes, or during the encode round) leaves nothing for the next command (tests `cancelled_compress_*`, `cancelled_adjust_*`); a finished command drops them too.

## Events, hooks

Events as the TS dispatches them (`uw-change` per `changed()`, `uw-tbmode` for entering/leaving a box). A command that runs another inside itself (the wrap of the layout
dialog, of a position) carries the inner change set (`carry`): the inner `done` used to swallow the events (found by the harness: `isl` and `ip`).
Hooks used: F6's none; D2a's `begin_step`, `changed`, contexts (`enter_textbox_at`, `exit_textbox`, `reenter_textbox`); F4's reader helper (above).

## Decisions outside the TS semantics (for the milestone gate)

| # | Decision | Why |
|---|---|---|
| F7-D1 | `compressImages` resamples with an area average (`resample`), the TS with `drawImage` and `imageSmoothingQuality = 'high'`; the harness feeds the TS's encoded bytes, so the model and the XML are compared and the `enc` facet of `cmp` is accepted by name (3 steps) | the browser's smoothing is not reproducible; the alternative (a source rectangle and target size on `Job::EncodeImage`, the shell resamples) is a shared protocol change — **maintainer decision** |
| F7-D2 | The contour of a tight/through wrap: the port crops, flips and scales the decoded picture (`visible_region`: nearest sample, at most 480 px) before `wrap_contour`; the TS draws the same region through a canvas (smoothed when scaled). Equal for pictures at scale 1; the harness only asks a contour of an uncropped, unflipped picture and replays the TS's already rasterised region (the `gid` of the contour canvas) as the decode answer, so the port's crop, flip and 480 px scaling in `visible_region` is never compared with the TS, not even for the 600x40 image (no oracle for it) | the browser's scaled draw — or a "render region" shell job — **maintainer decision** |
| F7-D3 | Layout facts are arguments, not oracle calls: `ObjFacts { rect, frame }` of `SetMoveWithText`, `SetLayout`, `SetPosition`, `Align*`, the placement `PlaceAt` after a command that floats an inline picture, the page of an entered box (`InsertTextbox.page`) | the model has no layout; the alternative is a `LayoutOracle` method (as D2a-C2 asks for header/footer parts) — **maintainer decision** |
| F7-D4 | The textbox `ViewsCopied` after an undo (D2a-C3 open item): the copied views stay as D2a leaves them on re-entry | brief item, for the gate |
| F7-D5 | The shell queries return the MODEL values (EMU, 60000ths of a degree); the `/ 12700`, `/ 60000` conversions, the label texts (`Caixa de Texto N` is built by the core, the gallery names are the shell's) and `selectedImagePreview` stay in the shell | units and canvas are the shell's |
| F7-D6 | `selected_object_count()` counts every selected object; the TS counts the handles `enumFloats()` finds on the laid-out pages (`selectedFloats().length \|\| 1`). Accepted by name when a multi-selection exists (3 steps) | layout |
| F7-D7 | (withdrawn) The first version of this record accepted the `paras` and `docxml` facets after an `insertImage` as "the page's timing". It was a port omission: the F7 commands ended with the bare change set and never ran the settle (`syncRunRPr`, `syncSections`, `syncNoteSettings`) or `price_history`. Every F7 command that takes a step now ends in `finish()` (`finish_if_stepped`); the facets are compared without any acceptance | review finding, fixed |
| F7-D8 | `apply_drawing_xml` keeps the selection with the RUN (the TS `floatSel` is the run): a drawing that stops floating drops out of the index, and `settle_float_sel` (in `change_set`) drops an inline picture the text selection moved off, which the TS paint does through `selectedFloat()` | model identity |
| F7-D9 | The depth-64 walk of nested stories (`loc.rs`), the 1,024-picture and 4,096-answer caps, the 64 Mpx `MAX_PIXELS` cap on a decode answer (Compress, Adjust, contour) and the skip of a decode answer of width or height 0 or with fewer than `w*h*4` bytes (`compress_continue`, `visible_region`; `resample` returns blank for a 0-sized source) | stack and memory safety on hostile models |
| F7-D10 | Typing, Enter, Backspace and `insertImage` with an object selected (outside a box): the TS keeps `floatSel` as the RUN OBJECT, so whether the selection survives depends on whether the TS edit engine replaced that object (`fs` is `-` after about 40% of these steps, the object kept in the others); the port keeps the selection by position and models no run identity (runs are values). Not reproduced: the generator replaces these four ops by a text selection while an object is selected (`UO_F7_INCLUDE=sel` puts them back: about 30 of 40 documents then differ on `fs`/`pane`/`st`/`cnt` at the first such step) | no run identity in the model; the decision for the gate: either an identity token per object run in the edit engine (D2a) or the shell drops the selection on text input. Part of the recorded divergence is a harness artifact: the harness calls `el.type()`/`pressBackspace()` directly, while the element's real keydown path with a float selected sends Backspace to `deleteSelectedFloats` and a character on a selected text box to `enterTextbox` (`universal-write.ts` 10651); what a user can reach is typing over a selected inline picture |
| F7-D11 | `createDrawnTextbox` inside a box or a note is refused (the TS nests the new box in that story and cannot place it: the layout has no frame for it); the draw mode of the UI leaves the box first. The generator replaces `cdt` by a click out of the box while a box is in edit | not reachable from the UI |

Replicated TS quirks (not decisions): `insertImage` replaces the object run at its end by a plain text piece; free-form strings of the commands (dash, compound, preset ids,
geometry names) are written into the XML as given (a quote in a dash name breaks the file: the TS does the same; the hostile tests use markup-free strings there);
`setImageLayout` with `wrap: inline` on a text box takes a step that changes nothing; `compressImages` returns 0 without touching the history when nothing is selected.
