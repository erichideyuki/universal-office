## Decisions outside the TS semantics (for the milestone gate)

| # | Decision | Why |
|---|---|---|
| F5-D1 | **The note editing list is NOT flattened** (D2a-C1, gate question 3): a note is its `Story` (top-level paragraphs and table anchors) and is edited through `EditContext::Note`; every F5 helper reaches the note through `note_story`/`note_story_mut` | the TS flattens the cells of a note into its editing paragraphs and re-aligns the blocks with `reconcileBlocks` at exit/save; porting that is a change of D2a's context core (`story_of`, the `nt` undo step). By reading, an undo in a note with a table gives the TS only JSON-copied paragraphs, which `reconcileBlocks` cannot match with the originals (the cells would be emptied). No oracle case: the corpus has 221 notes in 67 documents and none holds a table; `session_d2b_f5.rs` records the Rust behaviour |
| F5-D2 | `convertNotes` copies the note through the undo normalisation | `structuredClone` keeps explicit-`undefined` keys, `NaN` and `-0` that the JSON-like normalisation drops; visible only on such values inside converted notes |
| F5-D3 | Commands return a `ChangeSet`, not the TS value: the id of an inserted note is in the `NoteMode` event, the number converted is `last_converted_notes()`, the booleans of `open`/`goTo`/`next`/`show` are the events and the selection | the command protocol (G15), as F6-D4 |
| F5-D4 | A part that `ensureNoteParts` cannot read leaves the package as it is | the TS would throw after the snapshot |
| F5-D5 | `goToNoteRef` refuses in the header/footer and text box contexts | the TS has no guard and puts a body position in the header's selection (a later `TypeError`); found by the no-panic test |
| F5-D6 | `noteTipAt`, `noteRunAt`, `caretKey` as TS objects | pointer hit tests and hover text are the shell's |
| F5-D7 | A reference whose `kind` is neither `footnote` nor `endnote` is not listed | the reader produces only those two |

Replicated TS behaviours (not decisions): `setNoteOptions` takes a step even when nothing changes; `convertNotes`
inside a cell indexes the cell's paragraphs with the body references' paragraph numbers; the package is the same at
every save, so settings written by an earlier save stay when an undo returns to the file's options; `enterNote` etc.
are D2a's.

### Section objects after an undo (found by the Chromium capture; D2a-level)

In the TS the `sectPr` of a section is one object, shared by the model and the effective section the layout and the
save read (`fullDoc.sections`). `setNoteOptions` mutates it in place; an undo puts a JSON copy in the model while
the effective sections keep the old object until `syncSections` runs — and it returns without running in a cell or a
note. So a note option set in a note after an undo is **not written by a save made before the caret leaves the note**
(and the next body refresh resyncs). The session reproduces it: a change of a `sectPr` makes a new `Arc` (the undo
step keeps the old one) and passes it to the sections that held the old one (`edit_sect_pr`); a restore gives every
`sectPr` a new `Arc`; and the settle runs the sync that was due during a cell/note/header edit at the next settle of
the body context (`SectionState.pending`). D2a's own captures only reach this through F5. Confirm at the gate that the
quirk is kept (it loses an edit in the file; the fix is one sync before the save in every context).

## For the milestone-2 gate

1. **D2a-C1 / question 3**: the TS flat note list is not ported (F5-D1); notes with tables are rare (0 in 2,753 corpus
   documents). The seam is `note_story`/`note_story_mut` plus `EditContext::Note`/`ContextStep::Note`. Decide: port the
   TS (flat list + `reconcileBlocks`, with its lossy undo) or edit notes as stories like cells (behaviour change only
   for notes with tables).
2. The TS section-object quirk above (keep for parity, or fix with a sync before the save).
3. `EditState.body_sect_pr` is now in the undo step (F4 reuses it for page set-up).

## Parity

Two harnesses, both at 0 mismatches:

1. **The element in Chromium** (`js/capture-d2b-f5-session.mjs` → `tests/parity/d2b-f5-session.capture`, replay
   `tests/parity_d2b_f5_session.rs`): 60 corpus documents (those with notes or several sections first) × 60 seeded
   steps: **48,600 facets equal, 0 mismatches, 0 accepted**. Per step the D2a facets (`paras`, `sel` = the body's
   selection, `anc`, `ev`, `flags`) and F5's: `csel` (selection inside a cell or note), `ctx`, `no` (options of both
   kinds and the counts), `np` (the note settings JSON), `ref` (references), `nts` (every note's content), `sect` (the
   note props of every section's `sectPr`) and, with each save (every 8 steps), `docxml` and `parts` (`footnotes.xml`,
   `endnotes.xml`, `settings.xml`, `styles.xml`, the content types, the rels). Mix: 353 note insertions (both kinds,
   marks, tracking), 457 option changes (document and section scope), 199 conversions, 183 opens, 150 go-tos, 230
   nexts, 115 shows, typing/Enter/Backspace/Delete inside notes (1,559 steps in a note), 14 cell entries (118 steps
   in a cell), 310 undos and 147 redos, 385 saves with edited note settings.
2. **Node, the pure rules** (`js/capture-d2b-f5-ops.mjs` → `tests/parity/d2b-f5-ops.capture`, replay
   `tests/parity_d2b_f5_ops.rs`): `nextNoteId`, `effectiveNoteOptions`, `ensureNoteStyles` (both kinds, the second on
   the sheet the first changed), `convertNoteContent` per note over 400 documents, and `notePropsOf` over 600
   generated option sets (NaN, ∞, odd strings): all equal.

Parity rounds: **3**, none a bug of the notes logic: (1) harness: `state.s` is the body's saved selection in a note,
so `csel` was added and `enterCell` is not called inside a note; (2) the section objects after an undo in a note
(D2a-level, above); (3) the sync due during a note edit (`SectionState.pending`). The D2a/F1/F2/F6 suites run in the
final run of the whole `uo-docx` suite.

## Security (no panic)

`nopanic_d2b_f5.rs`: 251 corpus documents × 150 hostile steps (note ids NaN/−0/1e300/∞, options NaN/∞/huge/odd
strings and columns, marks with lone surrogates and NUL, selections far outside the story, carets outside a note,
the editor locked in the middle, every command from body, cell, note and header/footer contexts, undo storms), then
300 undo + 300 redo and a save that reopens: **every save reopened**; 75 byte-mutated documents (19 opened and
hammered, 56 refused by the reader). The test found F5-D5. No `unwrap`/`expect`/`panic!`/indexing in `notes.rs`
(clippy `-D warnings`, native and `wasm32-unknown-unknown`, `--features canon,session`; `tests/grep-bans.sh` clean).
