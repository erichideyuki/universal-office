# uo-docx D2b-F3 — tables (declarations and process metrics)

*(Sonnet, hybrid mode, 2026-11-05; nothing committed.)* Frontier F3 of the editing session
(`core/docs/modules/uo-docx.md`, "D2a — session (architecture)" and "D2b frontier briefs"): the table
commands of the editor, over docx-core `table-ops.ts`, `table-sort.ts` and `table-formula.ts`. Files:
`session/ops/tables.rs` (the commands, `tableSel`, `clearSelectedCells`, the edit protocol) and
`session/ops/tables/{table_ops,sort,formula}.rs`. TS sources (frozen `d0f45bc5`): `universal-write.ts`
19250–19960 (the table block), 19960–20140 (borders, shading), 20200–20260 (`saveTableStyle`), 20700–20830
(`editTableAt`, edge resizing), 20995–21130 (`clearSelectedCells`, `tableSelKey`), 21190–21215 (`tabNewRow`,
`moveTableRow`), 21215–21470 (formulas, `setTableProperties`), 17636 (`resizeTableColumn/Row`);
`table-styles.ts` `ensureTableStyle`. `TOps.relink` is a no-op here (a cell's story is stored once).

`SetTableProperties`, `InsertFormula`, `TabNewRow`, `MoveTableRow`, `ResizeTableColumn/Row`. Queries:

What the TS reads from the layout comes as an argument (`TableLayoutIn`: the content width, the displayed height of
every row of the target table): the session never lays out (as D2a's contexts).

## Key orders built (U6)

Every `delete`, `x.k = v`, `{ ...a, k: v }` and `Object.assign`-like patch goes through `word::obj`
(`delete`, `set`, `set_undefined`, `spread`); a patch of `setCellProps/RowProps/TableProps` is the patch object
itself (a key held as `undefined` deletes, a value is a JSON copy). `row.trPr = { ...(row.trPr ?? {}), gridBefore, wBefore }`
= clone + `set` in that order. `syncLegacyCell`: `gridSpan` set, `widthTwips`/`shadingHex`/`borders` set or deleted.
The `Cell` JSON/canon views (`paragraphs`, `tables`, `blocks`) are the type's fixed order (the TS places `blocks`
after the legacy keys in some paths; not observable in the canonical digests).

## Events (in the order the TS dispatches them)

`editTable`: `uw-change` (`snapshot`), then `uw-cellmode:false` (`exitCell`) and `uw-cellmode:true` (the cursor goes
back into a cell); `Sort` of a table with merged cells: `uw-sort-error` (no step); `SetTableStyle`/`SaveTableStyle`
when the sheet changes: `uw-styles-change`. `Sort`'s message is the English one (the shell translates).

## Decisions outside the TS semantics (for the milestone gate)

| # | Decision | Why |
|---|---|---|
| F3-D1 | Spans are integers `1..=1_000_000`; `NaN` is 1 | the reader may store any double |
| F3-D2 | An operation that cannot run (position outside the table, a table it cannot place) changes NOTHING and takes no step: the table is edited in place and put back on `Err` | the TS throws a `TypeError`, sometimes after the snapshot (D2a-T1) |
| F3-D3 | An operation that would create more than 1,000,000 cells (Insert Table, split, text to table) is cut (`rows`) or refused | memory (Word's own limit is 2 million) |
| F3-D4 | The formula parser nests at most 200 levels (the syntax error text) | the TS overflows its stack |
| F3-D5 | `cloneTable` keeps image bytes | the TS JSON clone turns `Uint8Array` into an index-keyed object; the capture compares tables without images and relinked |
| F3-D6 | Layout inputs are arguments (`TableLayoutIn`) | the session never lays out |
| F3-D7 | `InsertTable` and `ConvertTextToTable` do nothing in a note, header/footer or textbox context | the TS inserts into the BODY's anchors with the context's paragraph indices |
| F3-D8 | `rowHeights`-based commands read `row_heights[r]`; a missing row is 0 | as the TS sum over no boxes |
| F3-D9 | The border pen is the shell's: `SetCellBorders` carries the resolved spec | `borderPen` is element state with a `uw-borderpen` event |
| F3-D10 | `styleOf(p).alignment` reads the document's styles only (the editor's built-in `STYLES` table for a style missing from `styles.xml` is not consulted) | never differs for documents with a styles part |
| F3-D11 | Built-in table styles are found by name in the generated data without expanding all 247 | cost |
| F3-D12 | `shift_anchors` in a cell (D2a file) | harness finding, above |
| F3-D13 | The body selection saved when a cell is entered is restored as it is, even past the paragraphs (the table commands can leave it stale, as the TS: parity found it clamped = different) | the no-panic test does not assert it |

Replicated TS quirks (not decisions): `toggleRepeatHeaderRows` reads `getTableState()` after the cursor left the cell,
so without a selection of cells it can only turn the header ON; `setTableCellMargins` returns `select`, the style
and border commands `keepTableSel`; `splitCells` copies the FIRST piece (already resized) for the next pieces;
`insertTable` splits with the guarded `splitParagraph`; `editTable` leaves the cell even when the operation changes
nothing.

## Memory (measured; see the run output)

M1 (`memory_d2b_f3.rs`): whole session lives with hostile table commands return the live bytes (0 B). M2: soak flat.
M3: a command on a 3,000 × 6 table allocates at most 4× the table (the table is copied once, copy-on-write against the
undo step); numbers in the run output.

## Security (no panic)

`nopanic_d2b_f3.rs`: hostile arguments (NaN, ±∞, 1e300, `i64::MIN/MAX`, hops past the tables, merged cells, control
characters) in every command over corpus documents and byte-mutated ones, with undo/redo storms and a save that reopens;
hostile formulas; the 32767 × 63 table is cut to 1,000,000 cells.
