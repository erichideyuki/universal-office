## Key orders built (U6, `obj::set`/`assign`/`spread`/`set_key_order`)

- Every patch is built key by key in the TS literal's order with `obj::set` / `obj::set_undefined` (the macros `rset!` in
  `format.rs`, `pset!` in `paragraph.rs`: a value is a key, `None` is a key holding `undefined`), and applied with the D2a
  ops (`Object.assign`): `toggleRunProp` `{ [key]: on, doubleStrike: false | strike: false }`; `setUnderline`
  `{ underline, underlineStyle }`; `setUnderlineColor` `{ underlineColor, underlineTheme, [underline, underlineStyle] }`;
  `setFontFormat` in the order of its `if`s (3176–3205); `setColor` `{ color, colorTheme }`; `growFont`, `setFontSize` …;
  `CLEARED_RUN` = `spread(DEFAULT_RUN_PROPS, { szHalfPt, color, highlight, fontAscii, vertAlign, charSpacingTwips,
  charStyle: undefined })`; `CLEARED_PARA` (ten keys) + `styleId`; `indentsDirect` `{ indentLeftTwips, indentRightTwips,
  indentFirstLineTwips }`; `spacingDirect` `{ [auto], [twips] }`; `setParagraphLayout`'s `{ ...d, ...spacingDirect }`;
  `setSpaceAfter` `{ spaceAfterTwips, spaceAfterAuto: undefined }`.
- The pending props of a caret: `{ ...(pendingProps ?? currentProps()), ...patch }` = `obj::spread(&cur.props, &patch)`; the
  symbol keys the spread copies (`RPR_REF`/`RPR_EDITED`) are `CarriedProps::link` (D2a, P2), kept.
- Text effects: `{ ...(p.textFx ?? {}) }` copied, then `fx[k] = …` (`obj::set`) / `delete fx[k]` (`obj::delete`) per part in
  patch order; `undefined` (`Object.keys(fx).length ? fx : undefined`) as `set_undefined`.
- `ParagraphBorders` `{ ...cur }` then `out[side] = …`/`delete`; `BorderEdge` is declared `{ style, sizeEighthPt, color,
  spacePt }`: `setParagraphBorders` builds `{ style, sizeEighthPt, spacePt, ...(color ? { color } : {}) }` and sets the order
  `[0, 1, 3, 2]` when it has a colour; the presets/`toggleBorder` edges have no colour (declaration order = TS order).
- `tabsDirect` entries `{ posTwips, align, [leader] }`, `dedupeTabs` `{ ...t, pos }` (pos stays first), the text-effect
  gallery values and `textGradient`/`outline`/`refl`/`shadow` (the structs' declaration order is the TS literal's; verified
  by the JSON compare of all 15 gallery entries).
- The horizontal-line run `{ text, props, shape }` and its shape `{ style, widthTwips, heightTwips, hr, hrAlign, rawVml }`
  (increasing declaration indices: no recorded order).

## Decisions outside the TS semantics (Opus check first)

| # | Decision | Why / evidence |
|---|---|---|
| F1-D1 | The underline button's style (`ulButton`, 3027, element state outside the undo steps) lives in the SHELL: the commands that read it take it as `button` (`ToggleRunProp` for the underline key, `ToggleUnderline`, `SetUnderlineColor`), and `FormatCmd::underline_button_after(current)` says what it becomes (`setUnderline(style ≠ none)`, `setFontFormat({ underline })`) | `Session` has no field for it and F1 may not add one; the replay keeps a `Shell` that applies the same rule; 55,384 results equal |
| F1-D2 | The format painter (`painterProps`, `painterLock`, 4666–4710) is the SHELL's: `Session::copy_format()` returns the `FormatPainter` (the run and paragraph formatting plus the symbol-key link), `FormatCmd::ApplyPainter { painter }` applies it (the lock/unset logic is UI). `copyFormat` reads the caret's `currentProps()`, not the pending props, exactly as the TS | same reason; the painter is not undo state |
| F1-D3 | `Object.assign(run.props, painter.run)` copies the SYMBOL keys `RPR_REF`/`RPR_EDITED` too, so the painted runs adopt the source's `w:rPr` at the next `syncRunRPr` (visible in `paras` as `rpr`). The D2a ops patch only `RunProps`, so `merge_painter_link` sets `Run::rpr_link` after the apply on the runs that START inside the range (a merge keeps the first run's props, which is the TS rule) | found by the parity run (round 1: 4 mismatches, all `pt` ops, `rpr: {sz: 40}` missing on the painted run); 0 after |
| F1-D4 | `insertHorizontalLine`'s shape style is `{ fill: 'A0A0A0' }` in the TS (no `geom`); the Rust `ShapeStyle::geom` is required, so F1 sets `geom: "rect"`. The Chromium capture applies the same normalisation to the TS state (`geom: 'rect'` on `hr` shapes without one). The saved XML is the raw VML either way (`rawVml`), compared in the `docxml` facet | a `req` field cannot be absent; changing the model (`geom` optional) is the D1a owner's call |
| F1-D5 | `TEXT_EFFECT_GALLERY` labels (`Lbl`) and the menus' presets (`TEXT_REFLECTION_PRESETS`, glow sizes, outline weights/dashes, `NUMBER_STYLES_OT`, `LIGATURE_OPTIONS`, `GRADIENT_DIRECTIONS`) stay in the shell (chrome data, `chrome-effects.ts`); only what the model commands read is ported (the 15 `fx` values and their builders) | labels are UI; the values are compared by JSON against the TS |
| F1-D6 | Arguments are typed Rust values, not JS objects: colours `ColorArg::{Hex, Theme}`, patches as ordered `Vec<FxPart>`/`Vec<OtPart>` (the order is the TS `Object.entries` order), `Option<Option<ColorArg>>` for `string \| ThemeColorRef \| null \| undefined`, `Indent { delta: i8 }` for `1 \| -1`. `Command` stays small because `FontFormat` and `FormatPainter` are boxed | the codec (G15) builds these from the binding's input; no semantics change |
| F1-D7 | Commands run before any change check the TS's own guard (`!model || locked()`); errors can only be `CommandError::Position` (a stale position inside an op), after which the step is discarded (`discard_step`) so no empty undo step stays; `locked`/read view answer `Done` with no events like the TS | M1 tests (locked, read view, policy) and the no-panic run |
| F1-D8 | Contexts: the commands work in the story of the edit context (cell, note, header/footer, textbox) through `paras()`/`paras_mut()`. They are covered by an M1 test in a note and by the no-panic run; the Chromium harness (the D2a one) drives the body only, so the F1 ops are NOT compared in contexts | declared coverage gap, same as D2a's harness |
