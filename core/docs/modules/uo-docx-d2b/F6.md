# uo-docx D2b-F6 — review, comments and bookmarks (declarations and process metrics)

*(Sonnet, hybrid mode, 2026-11-05; nothing committed.)* Frontier F6 of the editing session
(`core/docs/modules/uo-docx.md`, "D2a — session (architecture)" and "D2b frontier briefs"): the review
commands (`revisions.ts` of the editor and the review methods of `universal-write.ts`), the comments and
the bookmarks and links, in `session/ops/revision_cmds.rs`, `comments.rs` and `bookmarks.rs`. The accept /
reject rules themselves are D2a's `session::revisions` (docx-core `revisions.ts`). TS sources:
`universal-write.ts` 3486 (`setLink`), 6105–6211 (bookmarks), 7711–7757 (`insertHyperlink`,
`removeLink`), 7869–7898 (comments), 7944–8300 (review), `editor/src/revisions.ts` (`MarkupMode`,
`MarkupOptions`, `DEFAULT_MARKUP`), `editor/src/references.ts` (the pure bookmark rules), `docx-layout/src/
revisions.ts` (`RevisionDisplay`, already in `word::revisions`).

`toggleTrackChanges`, `author`, `setMarkupMode` stay D2a's (`SettingsCmd`). Pure rules exported from

## Identity per construction site (G22)

No command of F6 creates a paragraph, table or drawing: bookmark marks, comment ids and link props change
the paragraphs in place (`paras.make_mut(i)`: the `ParaId` stays); `unlinkRuns` ends in `normalizeParagraph`
(in place). `acceptChange`/`resolveAll` use D2a's `revisions::merge_next` (the identity rule of the D2a
table). `insertHyperlink` types through D2a's `insert_typed` (new runs are values, no identity).

## Decisions outside the TS semantics (for the milestone gate)

| # | Decision | Why |
|---|---|---|
| F6-D1 | `applyRevisionScope` always runs the run guard over the WHOLE list (body, every cell, notes, header/footer parts), also when the list has no revision | the guard rebuilds the runs' props (their key order is part of the TS run signature the save compares, D2a-U6): skipping it saved a different `document.xml` (found by the parity capture, one mismatch in 44,400 facets) |
| F6-D2 | Header/footer and note stories are their top-level paragraphs; revisions in the tables of a header, footer or note are not listed nor resolved | the TS lists are flat (cells included); extends D2a-C1 (F4/F5 decide with the flat view) |
| F6-D3 | `getBookmarks` by-name sort (`localeCompare('pt-BR', { sensitivity: 'accent' })`, ICU) stays in the shell; `bookmarks(hidden, by_location)` gives discovery or location order | no ICU collation in the core (the Excel collation of uo-text is another order) |
| F6-D4 | Commands return a `ChangeSet`, not the TS value: `revision_count()` before and after is the number `acceptAllChanges` returns, `comments().last()` is the id `addComment` returns, an event tells whether a boolean command acted | the command protocol (G15) |
| F6-D5 | `formatDescription` (the balloon texts of tracked formatting, three languages), `revisionAnchors`, `goToBookmark`, `goToComment`, `navigateTo`, `getLink`, `getLinkTargets`, `revisionAtCaret`/`getRevisions` as TS objects | UI text, layout positions and scrolling or selection moves (shell / F9); the data they read is in the queries above |
| F6-D6 | `selectRevision` moves the selection only for a revision of the body's own list; another story's is scrolled to by the shell | as the TS (`e.story === 'body'`) |
| F6-D7 | `applyRun` (hyperlink patch) has no extra ranges (`extras()`): the session has no multi-selection yet | F9 adds them; `format.rs` (F1) has its own `apply_run` |
| F6-D8 | `nextBmId` is per session, not per element | a session is one document (the brief: "per document") |
| F6-D9 | Positions that name no paragraph answer `Err(Position)` before any change (`add_bookmark_marks`) | D2a-T1 |
| F6-D10 | Nested tables are walked to depth 64 only | stack safety on hostile models (the reader's field depth limit is 64 too); nothing real is deeper |
| F6-D11 | `inPlainTextControl` is implemented locally (`ops::bookmarks`, needs the sources) | not in the Rust `SourceStore`; F1 wrote the same rule in `paragraph.rs`: F4/F5 can move one copy to `model/sources.rs` |
| F6-D12 | `insertHyperlink` to a heading (`anchor: "p:N"`, body context) needs F10's `refBookmark`; until then `NotPorted` (no step left); an address or a bookmark anchor works | hook |
| F6-D13 | `insertHyperlink`/`removeLink` get the style through F2's `builtin_style_id` (defined on demand once F2 landed; with the interim stub a style the document lacked was `NotPorted`). The Chromium scripts only run the link commands on documents that already define `Hyperlink` (the element would rewrite `styles.xml`, which the `docxml` facet does not compare) | hook |

Replicated TS quirks (not decisions): `insertHyperlink` with `anchor: "p:N"` past the end returns after the
snapshot without discarding it (an empty step); `removeComment` takes a step even for an unknown id and has
no lock check; the comment list is not in the undo state; `acceptChange` without a revision only moves on.

## Security (no panic)

`nopanic_d2b_f6.rs`: 251 corpus documents × 150 hostile steps (revision and selection indices at
`u32::MAX`, comment ids NaN/−0/1e300/∞, bookmark names empty, 41 units, with NUL, non-BMP, hyperlink
addresses and anchors including `p:` with 20 digits, markup filters with unknown authors, lone-surrogate
comment text, the editor locked in the middle, cells, notes and header/footer parts entered and left between the
commands so that the review ones run in every context, undo storms), then 300 undo + 300 redo and a save that
reopens: **every save reopened**; 75 byte-mutated documents (12 opened and hammered, 63 refused by the
reader). No `unwrap`/`expect`/`panic!`/indexing in the F6 files (clippy `-D warnings`, native and
`wasm32-unknown-unknown`, `--features canon,session`).
