# uo-docx D2b-F2 — lists and styles (declarations and process metrics)

*(Sonnet, hybrid mode, 2026-11-05; nothing committed.)* Frontier F2 of the editing session
(`core/docs/modules/uo-docx.md`, "D2a — session (architecture)" and "D2b frontier briefs"): the numbering store
and the lists, the style sheet store and the styles, the three hooks the text family left for them, and the
save of the two parts. Files: `session/ops/lists.rs` (+ `lists/{store,rx,library,regex_tests}.rs`) and
`session/ops/styles.rs` (+ `styles/{sheet,xform}.rs`). TS sources (frozen `d0f45bc5`):
`universal-write.ts` 3500–4150 (lists), 4150–4660 (styles), 6630 (`builtinStyleId`), 23330–23473
(`ListLevelSpec`, `levelXmlOf`, `levelRPrXml`); `editor/src/numbering-store.ts`, `list-library.ts` (generated
data), `styles.ts`; docx-core `style-sheet.ts`, `word-styles.ts` (already `data::word_styles`).

## Identity per construction site

No TS literal in F2 creates a paragraph, table or drawing. Every change is `paras.make_mut(i)` (`ParaId` stays): `setParaAt`
(`applyParaProps` in place), `clearPara`, `retargetStyles`, `applyNextStyle`'s `next`. Numbering values are plain values.

## Two-phase jobs

None. (The picture bullet of `defineListLevel`, which needs the image size from the shell, is not part of this port: below.)

## Events

`uw-styles-change` (`syncStyleSheet`: every commit and every restore of a style version), `uw-change` and `uw-dirty-change`
(the step; `commitStyles` also marks dirty outside a step, as `setDirty(true)`), `uw-blocked` (the policy guard, also for the
guarded methods called from inside another: `inner_guard`). No other event.

## Hooks

Used: the hooks D2a declared for F2 (`list_enter_on_empty`, `list_backspace_at_start`, `apply_next_style`), now real.
Declared for others: `builtin_style_id`, `change_list_level` (above), `commit_styles`, `ensure_style_used`,
`numbered_raw`, `word_range_at`. Stubbed in another family's file: none.

## Parity

Three harnesses, all replayed exactly:

1. **The session in Chromium** (`js/capture-d2b-f2-session.mjs` → `tests/parity/d2b-f2-session.capture` →
   `tests/parity_d2b_f2_session.rs`): the frozen `<universal-write>` (bundle SHA in the capture), pt-BR page, 120
   documents × 60 steps of seeded scripts of every F2 command mixed with typing, Enter, Backspace (the hooks), selections,
   undo, redo and tracking. Facets per step: `paras`, `sel`, `anc`, `ev`, `flags` (as D2a), `sv`/`nv` (the style sheet and
   numbering text of now) and every 8 steps the saved `word/document.xml`, `word/numbering.xml`, `word/styles.xml`
   (the store saves, byte for byte). **61,679 facets equal, 0 mismatches, 1 accepted by name** (the F2-D4 throw, below).
2. **D2a-T4 resolved**: `parity_d2a_session` with its acceptance switched off: **59,520 facets equal, 0 mismatches, 0 accepted** (before: 59,256 equal + 264 accepted by name; the
   list rules of Enter/Backspace and `applyNextStyle` are real now, and `parity_d2a_ops` is still 126,868 equal)..
3. **The pure model files in Node** (`js/capture-d2b-f2-ops.mjs` → `tests/parity/d2b-f2-ops.capture` →
   `tests/parity_d2b_f2_ops.rs`): `styles.ts` + `style-sheet.ts` transformations and `DocNumbering` with the
   `list-library.ts` data over the `styles.xml`/`numbering.xml` of corpus documents (`Math.random` = xorshift32).
   200 documents × 40 style ops and 40 numbering ops: **48,000 facets equal, 0 mismatches** (226 of the TS calls
   throw and the Rust side answers `err` in the same places).
4. Regex rows: 868 results over 31 sites equal to V8; the library data are generated (`tools/gen-list-library.mjs
   --check`, the SHA of the TS source in the header).

Parity rounds: two, both harness findings: (1) the element's constructor draws one `Math.random()` (F2-D14); (2) the
TS exception of F2-D4 (accepted by name). No port bug came back from a facet.

## Memory, work and security

- **M1** (`tests/memory_d2b_f2.rs`): sessions over corpus documents with seeded F2 scripts (valid and hostile), 30
  undos, 30 redos, save -> drop: live bytes return exactly. The built-in style table is walked as the static slice it is
  (121 distinct names, tested), the blank document's latent styles are parsed per call only when needed, and the style index is
  memoised in the session: no process-wide cache (a first version kept two `OnceLock`s, ~21 KB, and the M1 of other families
  reported them as a leak the first time they ran inside a measured life). 10 corpus documents x 2 lives + the error paths: 0 B; the soak of 300 lives over 6
  documents is flat (a constant 21,376 B offset of the test, no growth; D2a's soak shows 34,049 B the same way).
- **M5**: 10,000 list toggles keep the numbering store at ≤ the history length + 3 versions and the history at its cap;
  the style sheet likewise over 400 edits. 10,000 list changes (the level format of a list item re-applied, one numbering version each): history 200
  steps / 755 KiB, numbering versions kept 202 (peak 202); 400 style edits: 202 versions kept; ≈ 10 ms per change in release
  (102 s for the 10,000; the test defaults to 3,000, `UO_M5_N=10000` for the full run). Toggling a list on and off adds
  an abstractNum each time, as the TS (the part only grows): 400 rounds are in the same test.
- **No panic** (`tests/nopanic_d2b_f2.rs`, `session_d2b_f2::hostile_parts_do_not_panic`): corpus documents, byte-mutated ones
  and documents with hostile `numbering.xml`/`styles.xml` (unclosed tags, huge ids, link cycles, empty ids), with NaN,
  infinities, huge levels, ids and names with quotes, markup and emoji, unknown styles, empty names, the policy and
  tracking on, undo/redo storms past both ends and a save that reopens. Every command answers a value.
- Work: a style command parses `styles.xml` a handful of times (as the TS, which memoises per version: the index and the
  parsed numbering are memoised here by `VersionId`); `sync_style_sheet` re-reads the sheet once per commit.
