# uo-docx D2b-F8 — the clipboard (declarations and process metrics)

Frontier D2b-F8 of `uo-docx` (milestone 2, Opus for the paste-tree boundary): copy, cut and paste as session commands, the
two-phase reads of the system clipboard and renders of Paste as Picture, the rules of `paste-html.ts` over a neutral
paste tree, the Office Clipboard (the ring of D2a), Paste Special with Paste Link, the paste under the formatting policy.

Files: `src/session/ops/clipboard.rs` (family API, `F8State`, queries) and `src/session/ops/clipboard/{tree,html,rx,
image,clone,copy,paste,sanitize,cells}.rs`; tests `tests/{parity_d2b_f8_ops,parity_d2b_f8_html,parity_d2b_f8_session,
regex_d2b_f8,session_d2b_f8,memory_d2b_f8,nopanic_d2b_f8}.rs`, `tests/d2b_f8_support/mod.rs`; scripts
`js/capture-d2b-f8-ops.mjs` (Node), `js/capture-d2b-f8-html.mjs` and `js/capture-d2b-f8-session.mjs` (Chromium),
`js/paste-tree.mjs` (the shell encoder), `js/regex-sites/d2b-f8.mjs`; data `tests/parity/d2b-f8-{ops,html,session}.capture`,

## The paste-tree boundary (F8-D1, `tree.rs`, `js/paste-tree.mjs`)

The shell keeps `DOMParser` and the CSSOM; every paste rule runs in Rust. For a `text/html` item the shell sends one
payload (format v1, little-endian, `str` = `u32` units + UTF-16LE):

```
"UOPT" u16 1 u16 0  str raw-html
u32 nodes; per node u8 kind (1 element, 3 text, 4 CDATA, 8 comment) u32 subtree-size
  element: str tagName, u16 attr-mask + strs (style class align face color size href src width height),
           u16 css-mask + strs (fontWeight fontStyle textDecorationLine textDecoration color fontFamily fontSize
           verticalAlign textTransform fontVariant fontVariantCaps display textAlign)
  other:   str nodeValue
u32 tables; per table u32 rows; per row u32 cells; per cell u8 flags (1 TH, 2 colspan, 4 rowspan), the strs,
  u32 pieces + strs (raw textContent)
```

- The node tree is `parseFromString('<!doctype html><html><body>' + fragmentOf(html) + '</body></html>').body` in
  pre-order (paste-html.ts:191, verbatim); the tables are the DOM half of `tablesFromHtml` (20544–20565, verbatim:
  top-level tables, the `:scope` row selector, the `TD`/`TH` children, `p, div, li` textContent or the `<br>`-split
  `innerHTML` re-parsed) over `parseFromString(html)`; the white-space rules, the grid and the merges run in Rust.
- An empty attribute or CSS value is sent as absent: every read treats `''` as missing (`if (fw)`, `getAttribute(x) ??
  ''`, `Number('') === Number(null) === 0`, `parseInt('') || 1` = `parseInt('1')`, `'' !== 'none'`). Proven by the HTML
  capture (0 mismatches over 1,200 inputs).
- Decoder: every length is checked against the bytes left before allocating; sizes must nest, node 0 is an element whose
  subtree is the whole list, leaves have size 1, unknown kinds/mask bits/trailing bytes are `Malformed`. Limits (F8-D2):
  64 MiB, 262,144 nodes, depth 1,024, 1,024 tables, 262,144 rows+cells, 65,536 pieces per cell. **Measured: Blink nests
  the fragment at most 513 deep** (a 2,000-deep `<div>` input gives 513 in the HTML capture), so 1,024 never refuses a
  browser tree. Over a limit or malformed: the HTML is ignored and `pasteData` goes on to the image / text branches.
- `htmlToParas` walks the tree with an explicit frame stack (walk, children with the `[if !supportLists]` state, the
  cells of a `<tr>` with `cur = p`): no recursion on hostile depth.
- The TS `Map`/`Set` lookups stay hash lookups (`wordListFormats` and the walker's `wordLists.get`: a `HashMap` over the
  insertion-ordered list; `cellsClip`'s kept cells: a `HashSet`), and the `@list` matcher stops at the last `}` (no
  `@list … {` start after it can match, the V8 regex would rescan to the end from each): 200,000 Word lists in 0.7 s,
  a 10,000 × 10 table copied in 0.3 s (M3, `nopanic_d2b_f8`).
- `js/paste-tree.mjs` is the future shell code (editor switch, queue item 9); `tree::encode_payload` is the Rust twin
  (tests, bindings). Chromium's CSSOM strings are the reference: Firefox/Safari shells will send their own
  serialisations (`700` vs `bold`…), exactly as the TS reads them today.

## structuredClone and the media (F8-D6, `clone.rs`)

`cloneDrawingRun`, `cloneBlocks` and `structuredClone(cellContent)` keep explicit-`undefined` keys and NaN, drop the symbol
keys (`rpr_link`, `FormatChange::old_link`), keep the textbox wrappers (`TxbxSrc`) and the textbox views. `TOps.cloneTable`
stays F3's JSON copy (`clone_table`). The TS objects hold the image bytes; a Rust run refers to its document's
`MediaStore`, so a clip carries its own payload list: copying maps source ids to the clip's (`MediaMap::ToClip`), pasting
maps them into the target (`MediaMap::FromClip`, the store dedupes equal bytes). Same bytes as the TS.

## Two-phase jobs

| Command | Job | Answer | Step |
|---|---|---|---|
| `Paste`, `PasteSpecialFormats`, `PasteSpecial` (no data read before) | `ReadClipboard` | `Clipboard{text, html_tree, image}`; `Failed` = no permission (the internal copy only); anything else = no data | the paste's |
| Paste as Picture (`mode: Picture`, Paste Special picture, `PasteAll` with a picture default) | `RenderClip` (one per picture, in order; the shell reads `render_clip_request()`) | `Rendered{png, w, h}`; `Failed` = nothing (the TS `null`) | after the PNG; `depth`/`start` measured then (as after the TS await) |
| `PasteData` with an image, Paste Special image | F7's `PictureCmd::Insert` (`DecodeImage`) | F7's | F7's |

The paragraphs of a picture paste are built when the command runs (their side effects — built-in styles, picture ids —
happen then, as in the TS) and travel in the pending command; a cancel drops them. What a clipboard command reported
before it went pending (the `uw-styles-change` of those built-ins) and the undo's change set of a `Repaste` wait in
`F8State::carried` and go in front of the session's next `Done` outcome (F8-D18): the completion, F7's picture insert
of an image paste, or — after a cancel or an error — the next command. `cancel_pending` needs no F8 hook.

## Decisions outside the TS semantics (for the milestone-2 gate)

| # | Decision | Why |
|---|---|---|
| F8-D1 | The paste-tree boundary as above (raw HTML + fragment tree with 10 attributes and 13 CSSOM longhands + the table grids from the shell's DOM half) | Rust cannot reproduce `innerHTML`/`:scope` exactly; every rule still runs in Rust |
| F8-D2 | Payload limits (64 MiB, 262,144 nodes, depth 1,024, 1,024 tables, 262,144 cells, 65,536 pieces); over a limit or malformed the HTML is ignored and the paste goes on to the image/text | the TS has no limits; the alternative is refusing the whole paste |
| F8-D3 | Protocol: `JobResult::Clipboard.image`, `JobResult::Rendered`, `RenderClip` without payload (`render_clip_request()`), `fragment` unused (reserved), `Event::Pasted` without detail; `contentWidthTwips()` is `PasteLayoutIn.content_width_twips` (web view), else the body section's print width (`this.model.sectPr` is the body's) | the session cannot see the layout or the view |
| F8-D4 | Paste Link between two sessions = `AddLinkSource` on the source, then `PasteLinkWith` on the target (the binding runs both); in one session one command. The source bookmark is added outside any step, as the TS | there is no `WeakRef` to another element |
| F8-D5 | `copied().html` needs feature `export` (`None` without it) | wasm size (G7); enabling `export` under `session` is the orchestrator's `Cargo.toml` call |
| F8-D6 | structuredClone semantics as above; the clip keeps its own media | model identity / media ids |
| F8-D7 | `pasteOptions`/`repaste` differ from the TS only after the history byte cap dropped steps | the cap (D2a) |

| F8-D10 | `NAMED[s]` of `cssColor` and `kw[s]` of `cssSizeHalfPt` find `Object.prototype` keys in the TS (`color="constructor"` → a function as the colour; `NaN` size); Rust: only the 18 names are colours, the proto names give `Some(NaN)` size | 1 HTML input accepted by name |
