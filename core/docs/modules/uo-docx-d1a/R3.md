# uo-docx D1a reader — frontier R3: declarations

Part of the record `core/docs/modules/uo-docx.md` ("Milestone 1 — D1a foundation", brief §B). One
table row per site; every row names the TS file:line. Item 9 rows need an Opus check before they land.

Scope ported (Rust files in `core/crates/uo-docx/src/read/`): `drawing.rs` (`drawing.ts`, all),
`vml_shape.rs` (`vml-shape.ts`, plus the part of `shape-xml.ts`/`picture-xml.ts` that
`vmlTextboxToDrawing` reaches, see item 9 row 1), `page_background.rs` (`readPageBackground`),
`watermark.rs` (`isWatermarkXml`, `readWatermarkXml`). The TS paths are in `write/packages/docx-core/src/`.
Public API: `read_wp_anchor(Option<Element>) -> Option<DrawingAnchor>`, `read_sp_pr(sp_pr, style_el)
-> ShapeStyle` (the signature fixed with R2), `read_cust_geom`, `vml_len_twips`, `parse_vml_style` →
`VmlStyle`, `vml_anchor`, `vml_color`, `vml_shape_style`, `srgb_of`, `anchor_child`,
`find_deep_drawing`, `text_of_drawing`, `read_page_background(el, &mut dyn FnMut(&str) ->
Option<ImageData>)`, `vml_textbox_to_drawing(el, id, VmlLang) -> Result<Option<String>, DocxError>`,
`vml_single_textbox`, `is_watermark_xml`, `read_watermark_xml(xml, &dyn Fn(Option<&str>) ->
Option<String>) -> Option<WatermarkInfo>` (`WatermarkInfo` is defined in `watermark.rs`, not part of
`FullDocument`).

## 3. Fields that can store NaN/±Infinity, keys stored as `undefined` (cleared bits)

Every number is a `JsNumber` (F1), so every NaN/±∞ below is representable without a declaration; the
parity corpus (`parity_drawing`) carries `NaN`, `1e999` and 20-digit strings in these attributes.

| Field | How a non-finite value gets there (TS file:line) |
|---|---|
| `AnchorPos.offset`, `AnchorPos.pct`, `DrawingAnchor.relativeHeight` | `parseInt` of 310+ digits is `Infinity` (`||0` removes NaN, not ±Infinity): drawing.ts:172, 174, 240 |
| `DrawingAnchor.wrapBox.*`, `wrapPoly` | ±Infinity points (drawing.ts:204); the area test is `false` when it is NaN (:211) |
| `ShapeStyle.adj[*]`, `rot`, `gradient.angleDeg`, `stops[].pos`, `fillTo.*`, `shadow.dx/dy/blur`, `fx.*Pt/*Deg` | ±Infinity from long digit strings (drawing.ts:293, 305, 321, 323, 331, 367-372); `dx`/`dy` are NaN when `dir` is ±Infinity (`Math.cos(±Infinity)`, :368-370) |
| `ShapeStyle.lineInset.w`, `line.widthPt` | NaN: `parseInt('abc') / 12700` (drawing.ts:381, 387, 394) |
| `ShapeStyle.fillAlpha` (VML), `line.widthPt` (VML) | `parseFloat` of a bad opacity is NaN (:493); `vmlLenTwips('.')` is NaN (`parseFloat('.')`), `?? 15` does not replace it (:499) |
| `ShapeStyle.cust[*]` (`CustPath` numbers, `f64`, F13) | a guide that evaluates to NaN/±Infinity (`at2 1e999 -1e999`, division by a NaN guide…): drawing.ts:540-563, 579-590 |
| `PageFill.angle`, `focus`, `focusPosition`, `colors[].pos` | `parseFloat`/`frac` of a bad string; `pct('%')` returns `parseFloat('%')` = NaN and `fo !== undefined` keeps it: page-background.ts:60-65, 82, 88-98 |
| `WatermarkInfo.widthPt/heightPt/sizePt` | `ptOf` of `width:x` is NaN; `sizePt` only `fs > 1` (so ±Infinity possible, not NaN): watermark.ts:105, 121-128 |
| `vmlTextboxToDrawing` text | `cx`/`cy` must be `> 0` (NaN returns `undefined`), but `dist*`, `posOffset`, `relativeHeight`, `adj` print `NaN`/`Infinity` as `String(n)` in the XML text (vml-shape.ts:55, 91, 96) |

Keys stored as `undefined`: **none** in the four files. The TS writes a key only inside an `if`
(`if (c.alpha !== undefined) …`, `...(cond ? { k } : {})`); the one assignment of a possibly
`undefined` value, `line.cmpd = ({…})[ls]` (vml-shape.ts:84), is a local of the XML generator and is
never observable. No `mark_undefined` is used.

## 6. Module-level / process-global state and its per-read replacement

None. The constant tables (`REL_H`, `REL_V`, `FLOW`, `VML_COLORS`, `relMap`, the escape and
shape-type strings) are `match` arms. `picture-xml.ts` has a module variable `rawSrc` that
`readPictureFormat` and `patchPic` set around reads of `rawOf`; the subset `vmlTextboxToDrawing`
reaches never reads through it, so no replacement is needed. `drawing.ts`, `vml-shape.ts`,
`page-background.ts` and `watermark.ts` have no counter or cache.
