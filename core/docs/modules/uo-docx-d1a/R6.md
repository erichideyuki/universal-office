# uo-docx D1a reader — frontier R6: declarations

Part of the record `core/docs/modules/uo-docx.md` ("Milestone 1 — D1a foundation", brief §B). One
table row per site; every row names the TS file:line. Item 9 rows need an Opus check before they land.

Scope: building the `SourceStore` during the read — the raw side of the lossless save. Rust file
`src/read/sources.rs` (+ the `SourcePart` change in `src/model/sources.rs`). TS: `source.ts` (`id`,
`addPara`/`addTable`/`addRow`/`addCell`/`addTextboxGroups`, `atOf`), `document.ts`
`captureParagraph` (2115–2159) and the segment loop of `readParagraph` (2046–2085, whose wrapper
computation is [`inline_wrapper`]), `fulldoc.ts` `wrapOf` (240), `readTable`'s `slice`/`openOf` (272–274) and
source records (323, 336, 347), `storyOf` (407), `groupOf` (412), the story and notes pieces
(`readNotesPart` 570–597), `commentIds`/`commentsSig` (769–770). **Not ported (session/writer side,
milestone 2, A2/G23):** the baseline signatures (`sig`, `runSig`, `propsSig`, `tableSig`, `sigHash`,
`baseline`), `paraRefs`/`tableRefs`/`memo`/`beginSave`/`pristine`/`tablePristine`, `genNumIds`,
`sectPrRaw`, `inPlainTextControl` and `plainTextSdt` (the two regexes of source.ts live there).

Public surface (what R4b/R4c/R5 call): `SourceStore::{add_para, add_table, add_row, add_cell,
add_textbox_groups, at_of, concat, record_comments}`; `capture_paragraph`, `PendingSeg`, `RunSide`
(+ `ObjSide`, `ElSpan`), `inline_wrapper`, `wrapper_spans`, `INLINE_WRAPPERS`; `story_of`,
`group_of`, `note_story_of`, `notes_part_of`, `note_item`; `table_source`, `row_source`,
`cell_source`, `open_of`; `span`, `el_span`, `opt_span`, `text_of`. R4c already uses the paragraph
half; **R5 uses**: `story_of`/`group_of` per top-level child (`produced` = `blockSrc(b) ?? 0` of each
block, `SourceKey(0)` for none), `table_source`/`row_source`/`cell_source` with the `pre`/`post` of
`unwrapRaw` (R5 ports `unwrapRaw`; a working test-only port is in `tests/parity_sources_blocks.rs`),

## 1. Numeric parse and rounding sites (uo-jsnum function used)

None: the source store holds ids, positions and text, never a parsed attribute. The ids and
positions enter the model as `JsNumber::Num(f64::from(u32))` (exact). Position offsets are
`usize` from the XML reader converted with `u32::try_from` (the reader's own positions are `u32`;
see 9).

## 2. Regex sites (template or matcher; dynamic ones named; row in `js/regex-sites/r6.mjs`)

| Site | TS | Regex | Matcher | Row |
|---|---|---|---|---|
| `openOf` of a table, row or cell | `fulldoc.ts:274` | `/\s*\/>$/` → `'>'` over the start tag | `matchers::self_closing_to_open` (template 6), in `sources::open_of`; unchanged text stays a span | `s1.open_of` |
| the paragraph's `open` (self-closing paragraph only) | `document.ts:2150` | same | same, in `capture_paragraph`; the result is an owned string | `s2.para_open` |

86 results (2 sites × 43 start-tag-like inputs: NBSP, U+2028, U+3000, U+FEFF, U+0085, tabs, newlines,
`/>` inside attribute values, text after the tag…) equal to V8; 38 of them run through the real
function on a parsed element (`tests/regex_r6.rs`). Not regexes (plain string operations, ported
as such): `raw.startsWith('<w:hyperlink')`, `name.endsWith('Pr')`, `INLINE_WRAPPERS.has(name)`.
No dynamic regex.

## 3. Fields that can store NaN/±Infinity, keys stored as `undefined` (cleared bits)

None. Every number of the store is an id, a position or a count (finite). No key is written as
`undefined` by this frontier: every optional key of a record is absent when the TS's conditional
spread omits it (`rPr`, `obj`, `objHead`, `pPr`, `tblPr`, `tblGrid`, `trPr`, `tblPrEx`, `tcPr`,
`groups`, `pre`, `post`, `wrapOpen`, `wrapClose`, `inner`), and `link`/`tip` are `''`, not
`undefined`, when the run has none (`para.runs[from]?.props.link ?? ''`). No cleared bit is set.
`inner: []` (an `sdt` whose content has no child but `*Pr`) is a present empty list
(`inner: Some(vec![])`), covered by a unit test.

## 4. Map/object iteration orders relied on (and key orders recorded with `mark`)

| Order | TS | Here |
|---|---|---|
| `paras`, `runs`, `tables`, `trs`, `tcs`: insertion order = id order | `source.ts` `Map`s | `JsMap` (IndexMap), ids issued in the TS order: the runs of a paragraph first (in order), then the paragraph (`captureParagraph`); a cell's blocks, then the cell; the row after its cells; the table after its rows (R5's order, checked by `parity_sources_blocks`) |
| `stories` by part path, `noteParts` by path, `txbxGroups` by textbox read order | `Map`/array | `JsMap`/`Vec`; the caller inserts in the TS order (document story first, then each header/footer when its section closes) |
| `StoryGroup.inner` and `blocks` in document order | arrays | `Vec`; `group_of` keeps the order of `produced` |
| key order of the store's records | object literals | **not observable**: the records are never stringified (`SourceStore.json` is `{}`) and the digest sorts keys; declaration order differs from the TS literal order for `ParaSource` (`raw`, `open`, `at`) |
| key order of the model objects that get a `src` | `p.props.src = id`, `t.src`, `row.src`, `cell.src` append a key to an existing object | `mark_appended`: when the object's insertion order is recorded (data-dependent), `src` is marked last; otherwise nothing is recorded (declaration order already puts `src` after what the readers assign before it). A unit test covers both cases |

## 7. `try {…} catch {}` sites and the partial result kept

None in this frontier's TS. One difference, by design: `captureParagraph` indexes `para.runs[i]!`
for `i` in a segment's range; a range past the runs (cannot happen with R4c's segments) would throw
in the TS. `capture_paragraph` stops the segment's loop at the end of the runs and keeps what it
had (unit test `capture_survives_out_of_range_segments`, no-panic loops with `from > to`, past the
runs and `usize::MAX`). Elements without positions (`pEl.s === undefined` makes the TS skip the
capture; a synthetic element would slice the whole text through `undefined` offsets) give an empty
text here instead; the callers never pass one (`read_paragraph` checks `positions().is_some()`).

## 9. Saturating/wrapping/truncating choices and data-shape deviations from A2

**Needs the Opus check (model/shared-file changes; none changes a result):**

| # | Change | Why |
|---|---|---|
| R6-1 | `SourcePart.text: Arc<str>` → `uo_opc::xml::Source` (the XML reader's shared buffer), manual `PartialEq` (`path` and text); `ReadCtx::source_part` now clones the handle instead of `Arc::from(&**doc.source())`; one-line adaptation of `tests/support/mod.rs` (`DOC_XML.into()`) | the brief's M1: the store must not copy part text. `Package::xml_part` hands the inflated bytes to the tree without copying and `Source` has no way back to `Arc<str>`, so the only copy-free type is `Source` itself. Measured: registering a 2.5 MB part and dropping the tree keeps **185 B** (handles), not 2.5 MB; a store of 20,000 paragraphs is 609 B/paragraph whether the paragraphs hold 10 or 2,000 characters (`tests/memory_r6.rs`) |
| R6-2 | `SourceStore`: `derive(Default)` replaced by a manual `Default` with `next: 1` | the TS `next = 1` (`0` is "no source"); the derived default started at 0, so the first id was 0 and `canon` of `next` was one lower |

**Choices inside the frontier (no model change):**

- Offsets are `u32` UTF-8 (`off()`: `u32::try_from(x).unwrap_or(u32::MAX)`, saturating; unreachable because the reader's positions are `u32`, and a saturated offset resolves to the empty text). The TS `at` and slices are UTF-16; the digest compares `at` in UTF-8 (F11).
- `SourceStore::id` saturates at `u32::MAX` (foundation).
- `SegSource.raw` of a field that joins children: the TS concatenates the slices (dropping what is between them); `concat` gives one span when the pieces are adjacent (the usual case, no space between `w:r` children) and an owned string otherwise: same content, same digest.
- `open_of` returns a span when the regex changes nothing (every non-self-closing start tag) and an owned string otherwise; `ParaSource.open` is a span for a non-self-closing paragraph (the TS applies no regex there, `document.ts:2150`) and owned for a self-closing one.
- `RunSide { rpr, obj }` carries the TS symbol keys `RPR_EL`/`OBJ_EL` (an element reference in the TS) as the element's `[s, e)` span, one per run next to the runs; R4c fills it. Not a model type.
- `record_comments`: `NumKey::new(c.id.to_number())` (a `null` id would be 0; the reader always gives a number) and `JSON.stringify(comments)` through `JsValue::json`.
- A segment range inside the runs is the only input the TS can express; out-of-range inputs are an accepted difference (7).

Unit tests (`tests/sources_unit.rs`, 16): ids from 1; capture with hyperlink, marker, object and
runs' ids; self-closing paragraph; `open`/`objHead`; out-of-range segments; inline wrapper rules;
`concat`; story/notes pieces; `group_of` (plain child, nested sdt, customXml, empty `inner`, equal
to the naive filter on 300 random trees, 400-deep nesting, 60,000 blocks); table/row/cell sources and the
`add_*` functions; key order of `src`; comments; elements without positions. Regex: `tests/regex_r6.rs`
(above). No-panic loops (`tests/nopanic_r6.rs`): every function over every element of the 400
synthetic documents and 400 seeded mutations of them (character replaced/removed/duplicated,
sdt fragments inserted, tags cut, non-BMP characters), with unknown, repeated and shuffled ids,
`part = u32::MAX`, run ranges `usize::MAX`: 494 parsed documents, 2.4 M blocks grouped, 0 panics.

Memory (`tests/memory_r6.rs`): M1 — every public function returns the live bytes to the start,
outputs dropped, over every element of a document with positions (and the no-positions path): 0 B.
The no-copy property: a 2.5 MB part registered in the store and its tree dropped keeps **185 B**;
the store of 20,000 paragraphs (one run each, a `pPr` and an `rPr`) is **609 B per paragraph**
(12.2 MB), identical (to the byte) for 10-character and 2,000-character paragraphs (2 MB and
42 MB of XML): the bytes depend on the number of records, not on the text. (The TS keeps four copies
of the text of every paragraph in its store: `raw`, `pPr`, each run's `rPr` and the segments' `raw`.)
M2 (soak) and M3 (budget) come with R5 and the memory-verifier.
