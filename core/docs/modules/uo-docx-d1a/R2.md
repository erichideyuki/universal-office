# uo-docx D1a reader — frontier R2: declarations

Part of the record `core/docs/modules/uo-docx.md` ("Milestone 1 — D1a foundation", brief §B). One
table row per site; every row names the TS file:line (`write/packages/docx-core/src/`). Item 9 rows need an
Opus check before they land.

Scope: `ooxml/parts.ts` → `read/parts.rs`, `styles.ts` → `read/styles.rs`, `table-styles.ts` (read side) →
`read/table_styles.rs`, `style-names-es.ts` → `read/style_names_es.rs` (the name table is
`data::style_names_es`; the built-in table styles are `data::table_styles_builtin`). Not ported here, by
design: `ensureTableStyle` and `addStylesXml` (`table-styles.ts:117`, `:148`) write the package and the sheet,
they are the session's (milestone 2); `CORE_TABLE_STYLES` and `localStyleId` are ported because the session
needs them next to the read side.

Shape of the port: the TS readers take the part text (`string | undefined`, the empty string meaning no part);
the Rust ones take the parsed part (`Option<&XmlDocument>`, parsed with the `DOCX` preset) and
`read_doc_formatting(ctx)` does the part lookup; every reader also has a `*_text` entry point with the TS
signature (empty text = no part, malformed text = `Err(DocxError::Package(_))` where the TS throws a
`SyntaxError`). The property readers (`readRPr`…) are R1's, `readSpPr` is R3's, `readBorderEdge` is R4a's.

## 7. `try {…} catch {}` sites and the partial result kept

None in `parts.ts`, `styles.ts`, `table-styles.ts`, `style-names-es.ts`. What the TS lets propagate:
`parseXml` of a malformed part (a `SyntaxError`), `Object.entries(unzipSync(…))` of a corrupt entry in
`pkg.getPart` (numbering images), `String.fromCodePoint` of a character reference past U+10FFFF. Rust:
`DocxError::Package(_)` from the XML reader / the package, with no partial result (the read fails at the
same place: `read_doc_formatting` reads the rels, numbering, then its images, styles, theme, settings, font
table). `tableStyleNameEs` of a name with a line terminator throws in the TS (item 9).
