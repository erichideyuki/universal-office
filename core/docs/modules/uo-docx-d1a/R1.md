`parseInt(v, 10)` → `parse::parse_int(v, 10)` everywhere; `int()` keeps the result only when finite,
so an `int` field is never NaN/±Infinity (it can be `-0`: `"-0"` is stored as `-0`).

## 2. Regex sites (template or matcher; dynamic ones named; row in `js/regex-sites/r1.mjs`)

One regex in the read side (`escX` is four chained global replaces of single characters). No dynamic
patterns. `tests/regex_r1.rs` runs the Rust matchers over the 89 inputs of `r1.mjs` (356 results,
V8 Node 24.15): all equal.

| TS site | Regex | Rust (template) | Rows |
|---|---|---|---|
| props.ts:369 | `/^(-?[0-9.]+)(mm\|cm\|in\|pt\|pc\|pi)?$/.exec(v.trim())`, groups 1 and 2 | `props::split_measure`: a `Cur` walk (template 5: `opt('-')`, `take_while1` digits-or-dot, then `is_one_of` for the unit on the rest; the digits and the unit letters do not overlap, so the greedy number never backtracks); `v.trim()` = `text::trim` | `r1.measure_test`, `r1.measure_number`, `r1.measure_unit` |
| text-effects.ts:178 | `t.replace(/&/g, '&amp;').replace(/</g, '&lt;').replace(/>/g, '&gt;').replace(/"/g, '&quot;')` | `text_effects::esc_x`: one pass over the characters (template 6; no replacement text holds a character a later replace looks for, `&` goes first) | `r1.esc_x` (the chain run as one `replace` through a `Symbol.replace` object) |

shorter than 4 gives `''`; see item 9, row 2).

## 3. Fields that can store NaN/±Infinity, keys stored as `undefined` (cleared bits)

Stored NaN/±Infinity (all `JsNumber::Num(f64)`, F1): a `measureTwips` match whose number text
`parseFloat` cannot read (`"."`, `"-."`, `"..5"`) is `NaN` (not `undefined`, so it is stored); a very long
digit string gives `±Infinity` (`parseFloat` and `Math.round` keep it); `Math.round(parseFloat(raw) * 50)`
of `"x%"` is NaN. Fields: `RPr.spacing` (499); `TabSpec.pos` (598); `SpacingSpec.before/after/line`
(611–621); `IndSpec.left/right/hanging/firstLine` (631–637); `FramePr.w/h/hSpace/vSpace/x/y` (652);
`TblpPr.leftFromText/rightFromText/topFromText/bottomFromText/tblpX/tblpY` (721); `WidthSpec.w` (430–431,
used by `tblW`, `tblCellSpacing`, `tblInd`, `tblCellMar.*`, `wBefore`, `wAfter`, `tcW`, `tcMar.*`);
`TrHeight.val` (783). Never NaN/±Infinity: every `int` field (finite guard), `textFill.alpha`,
`textShadow.*` (`|| 0`), every text-effects number (`num`). `-0` is stored where `parseInt("-0")` or
`Math.round(-0 * 20)` gives it (`sz`, `kern`, `spacing`…); the digest keeps it.

Keys stored as `undefined`: none. Every assignment of the read side is guarded (`if (v !== undefined)`,
`if (val)`) or has a defined value (`readRPr(el)` with `el` defined; `readRPr(..) ?? {}`). No
`mark_undefined`, the `cleared` masks stay empty (asserted by `no_key_is_stored_as_undefined`).

## 4. Map/object iteration orders relied on (and key orders recorded with `mark`)

| What | TS | Rust |
|---|---|---|
| keys of `RPr`, `PPr`, `TblPr`, `TrPr`, `TcPr` | assigned in the order of the XML children; a repeated child keeps the place of its first assignment (JS) | `put!` assigns and `mark`s every key (`KeyOrder::touch` keeps the first place); `w:rPrChange`/`w:pPrChange` mark `change` at the child's place |
| `RPr.fx`, `RPr.ot` | assigned last, after the loop (533–535) | marked after the loop |
| `TextEffects` (`glow`, `shadow`, `reflection`, `outline`, `fill`, `scene3d`, `props3d`), `OpenTypeProps` (`ligatures`, `numForm`, `numSpacing`, `stylisticSets`, `cntxtAlts`) | XML order of the w14 children (text-effects.ts:132–176) | `fx_set!`/`ot_set!` mark every key |
| `SpacingSpec` (code order: before, after, beforeLines, afterLines, beforeAutospacing, afterAutospacing, line, lineRule: 611–625), `FramePr` (dropCap, lines, w, h, hSpace, vSpace, x, y, hRule, wrap, hAnchor, vAnchor, xAlign, yAlign, anchorLock: 649–660), `TblpPr` (the six measures, then vertAnchor, horzAnchor, tblpXSpec, tblpYSpec: 720–729) | fixed code order that differs from the model's declaration order | every assignment `mark`ed in code order |
| `ColorSpec`, `RFonts`, `BorderSpec`, `ShadingSpec`, `UnderlineSpec`, `Lang`, `TextFill`, `TextShadow`, `IndSpec`, `NumPr`, `PBdr`, `TblBorders`/`TcBorders` (the `readBorders` map order), `CellMargins`, `TblLook` (the six-key list), `TabSpec`, `WidthSpec`, `TrHeight`, `RevisionInfo`, `RPrChange`/`PPrChange` (`{ ...info, rPr }`), `FxColor`, `FxFill`, `FxOutline`, `FxShadow`, `FxReflection`, `FxGlow` | built in a fixed code order equal to the declaration order | no mark (declaration order), checked by the order facet |
| attribute order in `elementXml` (`Object.entries(el.attrs)`, 183) | JS object order: array-index names first | `Element::attrs()` (uo-opc already orders them; unit case with `1="x"` and `2`/`10` names) |
| children order | document order | `child_elements()`, `children()` |
| `Set`s `TAB_VALS`, `LEADERS` (549–550) | membership only | `contains` over constant arrays |

The key-order stream is compared too (facet `<kind>.order`, 0 mismatches over 28,467 facets with both
streams; mutation-checked: removing one `mark` makes the facet fail).

## 5. Recursions (made iterative, or bounded by `max_nesting`)

| TS recursion | Rust |
|---|---|
| `readRPr` → `w:rPrChange` → `readRPr(w:rPr)` → … (props.ts:489) | a loop (`rpr_of`): the chain of nested `w:rPr` is collected top-down (the **last** `w:rPrChange` child of each element, and its first `w:rPr` child: the earlier ones are overwritten in the TS and pure), then the objects are built bottom-up; `change` is marked at the first `w:rPrChange` child. Depth is bounded by the XML limit (1,000: at most ≈ 500 levels) |
| `readPPr` → `w:pPrChange` → `readPPr(w:pPr)` → … (props.ts:672) | the same loop (`ppr_of`). `readPPr` → `readRPr` (w:rPr) is a call, not a recursion (`readRPr` never calls `readPPr`) |
| `elementXml` → `elementXml(child)` (text-effects.ts:184) | explicit stack of frames (`element_xml`): the start tag is written, the `>` before the first non-empty child output, `</name>` or `/>` at the end (the TS `kids ? … : <x/>`); depth bounded by the XML limit |

`change_chains_are_iterative` runs 480-level `rPr`/`pPr` chains, 2,000 sibling `w:rPrChange` and a
900-deep `elementXml` on a 192 KB thread stack. `enter_nested` is not used (no story nesting in R1).

## 6. Module-level / process-global state and its per-read replacement

None. The only module-level values are constants (`TAB_VALS`, `LEADERS`, the `W14` helper). No counters,
no caches, nothing in `ReadCtx`.

## 7. `try {…} catch {}` sites and the partial result kept

None in the read side of `props.ts` and `text-effects.ts`. (A part that does not parse is the caller's
concern: the parity facet records `xml=err` on both sides, 3 quirk cases.)

## 8. Aliasing (two model positions sharing one TS object) and how A2 gives the same result

None. Every reader returns a fresh object tree: `p.rPr` of a `PPr`, `change.rPr`/`change.pPr` and the
`?? {}` of a missing child are separate objects; `textFill.color`/`fx.fill.color` and `ligatures`/
`ot.ligatures` are separate values from separate reads.
